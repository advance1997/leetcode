## 1. 题目与接口约定

给定整数数组 `nums`，寻找一个下标，使它左侧所有元素之和等于右侧所有元素之和。当前元素不属于任意一侧，空区间的和为 0。多个答案返回最左侧下标，没有答案返回 `-1`。

原题范围：`1 <= nums.length <= 10000`，`-1000 <= nums[i] <= 1000`。

| 输入 | 输出 | 说明 |
| --- | --- | --- |
| `[1,7,3,6,5,6]` | `3` | 左侧 `1+7+3=11`，右侧 `5+6=11` |
| `[1,2,3]` | `-1` | 所有下标均不满足条件 |
| `[2,1,-1]` | `0` | 左侧为空，右侧 `1-1=0` |

仓库额外约定：`null` 抛出 `IllegalArgumentException`，空数组返回 `-1`；不修改输入。长度上限及元素范围不做逐项校验，正确性与数值安全按原题范围分析。

本次题意、难度、示例和约束核对于 [Doocs 公开题目镜像](https://github.com/doocs/leetcode/blob/main/solution/0700-0799/0724.Find%20Pivot%20Index/README.md)；官方链接供阅读，本次未直接验证官方页面。

## 2. 先理解目标：中心是“和的平衡”

“中心”不是数组长度的一半，也不要求左右元素个数相等。不要排序：顺序决定左右区间，排序会改变问题。

设候选下标为 `i`，需要比较的区间是：

```text
下标： 0 ........ i-1 |   i   | i+1 ........ n-1
区域：    左区间       | 当前项 |      右区间
求和：    leftSum      |nums[i]|     rightSum
条件：                leftSum == rightSum
```

负数允许出现，所以区间变长时和可能增加、减小或不变。此前 209 依赖正数单调性的滑动窗口规则不能直接照搬；这里固定候选位置并计算两侧和更自然。

## 3. 暴力解法：逐个下标重新求和

直觉上，依次尝试每个下标，每次都算出它左右两侧的和。

```text
for i 从 0 到 n-1：
    leftSum = sum(nums[0 .. i-1])
    rightSum = sum(nums[i+1 .. n-1])
    如果 leftSum == rightSum：返回 i
返回 -1
```

对应 `pivotIndexBruteForce`。每个候选都读取其余 `n-1` 个元素，最坏检查 n 个候选，共 `n(n-1)` 次累加，时间 O(n²)。只有几个整数变量，额外空间 O(1)。

瓶颈在于重复求和。例如检查下标 2 时算过 `nums[0]+nums[1]`，检查下标 3 又从头计算这两个数。相邻候选的左区间只多一个元素，却每次重建整个结果。

## 4. 如何想到优化：保存前缀，再消除右侧扫描

### 4.1 前缀和保存什么

定义 `P[i]` 为前 i 个元素之和，即半开区间 `[0,i)` 的和：

```text
P[0] = 0
P[i+1] = P[i] + nums[i]
```

于是下标 i 的左侧和为 `P[i]`，右侧和为 `P[n]-P[i+1]`。预先建一个长度 n+1 的前缀数组后，每个候选都能 O(1) 判断，总时间 O(n)、额外空间 O(n)。

这是从暴力推导出来的可行中间方案。但本题只从左到右检查一次，没有随机查询历史区间的需要，因此不必保存所有 P 值。

### 4.2 用滚动变量代替整个前缀数组

检查下标 i 时只需要当前 `P[i]`，可用 `leftSum` 保存。检查结束后令 `leftSum += nums[i]`，恰好得到下一步需要的 `P[i+1]`。

右侧怎么办？先扫描一次得到 `totalSum = P[n]`，再利用三个互不重叠的部分：

```text
totalSum = leftSum + nums[i] + rightSum
rightSum = totalSum - leftSum - nums[i]
```

这样左侧和可以增量维护，右侧和可以常数时间推导，两边都无需反复扫描。不需要哈希表，也不需要额外数组。

### 4.3 为什么必须先比较、再累加

进入循环时，`leftSum` 必须表示**当前元素之前**的和。若提前加入 `nums[i]`，它就变成 `[0,i]`，破坏区间定义。例如 `[2,1,-1]` 本来下标 0 两侧都是 0，提前加入 2 就可能漏掉答案。

对应 Java 关键片段：

```java
int rightSum = totalSum - leftSum - nums[pivot];
if (leftSum == rightSum) {
    return pivot;
}
leftSum += nums[pivot];
```

## 5. 图解与完整执行追踪

以 `[1,7,3,6,5,6]` 为例，第一遍累加得到 `totalSum=28`。第二遍开始时 `leftSum=0`。

| 当前下标 i | nums[i] | 比较前 leftSum | rightSum = 28-leftSum-nums[i] | 行为 |
| --- | --- | --- | --- | --- |
| 0 | 1 | 0 | 27 | 不相等，更新 leftSum 为 1 |
| 1 | 7 | 1 | 20 | 不相等，更新 leftSum 为 8 |
| 2 | 3 | 8 | 17 | 不相等，更新 leftSum 为 11 |
| 3 | 6 | 11 | 11 | 相等，直接返回 3 |

返回时的分割如下，方括号标出当前候选元素：

```text
数组： 1    7    3   | [6] |   5    6
下标： 0    1    2   |  3  |   4    5
       └── 11 ──┘           └─ 11 ─┘
总和：     11       +  6   +    11      = 28
```

因为题目要求最左侧答案，返回后不再检查下标 4、5。无解例 `[1,2,3]` 的总和为 6：

| 下标 | leftSum | rightSum | 行为 |
| --- | --- | --- | --- |
| 0 | 0 | 5 | 更新 leftSum 为 1 |
| 1 | 1 | 3 | 更新 leftSum 为 3 |
| 2 | 3 | 0 | 更新 leftSum 为 6，循环结束返回 -1 |

## 6. 正确性说明

循环不变量：每次检查下标 i 前，`leftSum` 等于 `[0,i)` 的元素和。

1. 初始化：i=0 时区间为空，`leftSum=0`，成立。
2. 判断：总和已经正确计算，减去左侧和及当前元素后，剩余恰是右侧和。因此相等时返回的一定是合法中心下标。
3. 维护：不相等时加入当前元素，得到 `[0,i+1)` 的和，保证下一轮成立。
4. 最左性与完备性：候选从 0 递增，首次相等就是最左侧答案；若全部不相等则确实无解。每轮下标增加，最多检查 n 次，必然终止。

空数组没有候选，直接走到返回 `-1`；单元素数组两侧为空，第一次检查即返回 0。

## 7. 复杂度、优势与代价

n 表示数组长度，以下为最坏时间与额外空间，不包含输入，返回值仅为一个整数。

| 方案 | 时间 | 额外空间 | 修改输入 | 优势与适用场景 |
| --- | --- | --- | --- | --- |
| 暴力重新求和 | O(n²) | O(1) | 否 | 直观，适合小规模验证，但重复计算多 |
| 完整前缀数组（推导方案） | O(n) | O(n) | 否 | 可以复用历史前缀以支持多次任意区间求和 |
| 总和 + 滚动前缀（实际实现） | O(n) | O(1) | 否 | 本题只顺序扫描，省去整个前缀数组 |

推荐法扫描总和 n 次、判断最多 n 次，合计至多两遍，O(2n)=O(n)。相对暴力法，在不增加渐进空间成本的情况下消除了重复累加；代价是要先求总和，并严格维护“不含当前项”的状态。即使下标 0 是答案，也需要先完成总和扫描。若后续需要任意历史区间查询，则完整前缀数组更合适。

在原题范围内，任何区间和的绝对值不超过 `10000×1000=10000000`，`totalSum-leftSum` 本身也是一个后缀的和，计算安全。若扩展数值范围，应重新分析并考虑 `long`，不能把本实现宣称为任意 int 数组均安全。

## 8. 边界与常见错误

| 输入 | 预期 | 关注点 |
| --- | --- | --- |
| `[5]` | 0 | 当前元素无需为 0，两侧为空即可 |
| `[0,0,0]` | 0 | 多个中心下标，只返回最左侧 |
| `[-1,1,2]` | 2 | 最右侧也可为中心 |
| `[-1,-1,-1,-1,-1,-1]` | -1 | 负数与无解 |
| `[1,-1,0]` | 2 | 总和为 0 不代表下标 0 必然成立 |
| `[]` | -1 | 仓库扩展，原题不提供空数组 |
| `null` | 抛出异常 | 仓库扩展参数校验 |

常见错误：右侧和只写 `totalSum-leftSum` 而忘记扣除当前元素；先更新左侧和再判断；找到答案后继续覆盖结果导致返回最右侧；把中心理解为左右长度相同；对包含负数的数组套用正数窗口的移动规则。

## 9. 面试表达与练习

可以这样复述：

> 我先枚举每个下标，重新计算两侧和，得到 O(n²) 的暴力解法。相邻下标的左侧区间只多一个元素，所以可以滚动维护前缀和。先求全数组总和，右侧和就等于总和减左侧和再减当前元素。每次先比较，再把当前元素加入左侧和。从左到右首次命中保证最左答案。两遍扫描，时间 O(n)、额外空间 O(1)，不改变数组。
