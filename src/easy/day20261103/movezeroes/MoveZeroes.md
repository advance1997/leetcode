## 1. 题目与关键约束

将 nums 中所有零移动到末尾，并保持非零元素的相对顺序。必须原地修改，不能复制数组来完成操作。方法返回 void，题面中的“输出”表示修改后的数组。

- `1 <= nums.length <= 10000`。
- 元素范围为 `[-2^31, 2^31 - 1]`，包含负数。
- `[0,1,0,3,12]` 修改为 `[1,3,12,0,0]`。
- `[0]` 修改后仍为 `[0]`。
- 进阶：尽量减少操作次数。

题意和约束已通过 [Doocs 公开题面镜像](https://github.com/doocs/leetcode/blob/main/solution/0200-0299/0283.Move%20Zeroes/README.md) 核对，本次没有重新访问官方题面，不标注未经核实的公司频率。

这里的“保持顺序”很重要：`[0,3,1]` 必须变为 `[3,1,0]`，不能排序为 `[1,3,0]`。把零与末尾非零元素直接交换，也可能破坏顺序。

## 2. 暴力方法：每遇到一个零，就把后面的元素搬过来

维护当前位置 currentIndex 和未处理区间的右边界 activeEnd（不包含）。遇到非零就向右走；遇到零则把后面尚未归位的元素依次左移，把零放到 activeEnd - 1，再缩小右边界。

```text
while currentIndex < activeEnd：
    如果当前值非零：currentIndex 加一
    否则：
        将 [currentIndex + 1, activeEnd) 整体左移一格
        activeEnd 减一
        nums[activeEnd] = 0
        重新检查 currentIndex
```

例如：

```text
[0,1,0,3,12]  遇到下标 0 的零
[1,0,3,12,0]  左移后 activeEnd = 4，重新检查下标 0
[1,0,3,12,0]  下标 0 非零，前进到下标 1
[1,3,12,0,0]  再次左移，activeEnd = 3
```

为什么搬移后不能直接前进？`[0,0,1]` 第一次搬移后变为 `[0,1,0]`，当前位置还是零，跳过就会漏处理。

为什么需要缩小边界？归位的零不应该再次进入搬移，否则可能一直处理尾部的零而无法终止。

每次左移都保持剩余非零元素的先后关系，归位尾部也只增加零，因此算法正确。每轮要么当前位置前进，要么右边界缩小，循环必然结束。

全零输入下，搬移次数为 `(n-1)+(n-2)+...+1`，最坏时间 O(n²)。只使用下标变量，额外空间 O(1)。

## 3. 优化思维：题目说“移动零”，实现可以先收集非零元素

暴力方法反复搬动同一批元素。如果前面有很多零，后面一个非零值可能被多次左移。

最终结果实际上只有两部分：

```text
[原顺序的全部非零元素 | 足够数量的零]
```

因此不必跟踪每个零去了哪里。先从左到右读取，把非零元素写到它们最终的前缀位置，最后统一清理尾部即可。

两个指针的职责：

- readIndex：读取当前位置，每轮前进。
- writeIndex：下一个非零元素应该写入的位置；只有读到非零才前进。

这与使用额外数组过滤的思路相同，但利用 `writeIndex <= readIndex`，可以安全地把结果写回原数组，省去 O(n) 的辅助空间。

## 4. 图解双指针：有效前缀不等于整个数组

下面读指针 r 是本轮读取下标，w 是下一次写入位置。竖线左侧是已经确定的非零前缀，右侧暂时不保证内容正确。

| r | 本轮读到 | w 变化 | 本轮处理后数组 | 已完成前缀 |
| ---: | ---: | --- | --- | --- |
| 0 | 0 | 0 → 0 | `[0,1,0,3,12]` | 空 |
| 1 | 1 | 0 → 1 | `[1,1,0,3,12]` | `[1]` |
| 2 | 0 | 1 → 1 | `[1,1,0,3,12]` | `[1]` |
| 3 | 3 | 1 → 2 | `[1,3,0,3,12]` | `[1,3]` |
| 4 | 12 | 2 → 3 | `[1,3,12,3,12]` | `[1,3,12]` |

```text
读取结束： [1, 3, 12 | 3, 12]
                     ↑
                     w = 3
尾部补零： [1, 3, 12 | 0,  0]
```

中途出现两个 1 或两个 3 没有问题：有效结果只在前缀中，尾部仍可能包含旧值。不能因为中间数组有重复就判断算法错误，也不能忘记最后补零。

## 5. 为什么原地覆盖不会丢失数据？

循环开始时保持以下不变量：

1. `0 <= writeIndex <= readIndex`。
2. `[0, writeIndex)` 恰好是原数组已读部分 `[0, readIndex)` 中的非零元素，顺序相同。
3. 从 readIndex 开始的未读部分没有被覆盖。

初始两个指针都为 0，条件成立。遇到零时只推进读指针，前缀不变。遇到非零时，将它追加到 writeIndex 对应的位置，再推进写指针。

由于写位置不超过读位置，只会覆盖已经读过的位置或当前自身，不会覆盖未来输入；按读取顺序追加也保证了稳定性。

扫描结束后，writeIndex 等于非零元素个数，前缀就是完整的目标非零序列。把其余位置设为零，正好补足原数组中的零数量。补零不触碰前缀，所以整体正确。

扫描与补零都具有单调递增的有限下标，因此一定终止。

## 6. 复杂度、优势与操作次数

令 n 为数组长度，k 为非零元素个数。

| 方法 | 最坏时间 | 额外空间 | 保持非零顺序 | 满足原地要求 |
| --- | --- | --- | --- | --- |
| 逐次搬移 | O(n²) | O(1) | 是 | 是 |
| 辅助数组过滤 | O(n) | O(n) | 是 | 否，违反本题要求 |
| 双指针压缩后补零 | O(n) | O(1) | 是 | 是 |

双指针扫描 n 次，补零至多 n-k 次，总计不超过 2n 次，不是两层嵌套循环，因此为 O(n)。数组越长，避免重复搬移的收益越明显。

代码跳过同位置写入，也跳过将已有零再次写成零：无零数组和全零数组都不会产生数组写入。一般情况下，非零复制至多 k 次，尾部写零至多 n-k 次，所以写入次数不超过 n，但会有条件判断的成本。

这并不代表写入次数对每个输入都最少。例如 `[0,1,1]` 中一个位置可能被相同值覆盖；进一步比较值可以减少此类写入，却会增加判断。原题进阶应结合具体操作模型分析，不能仅凭“一趟扫描”宣称最优。

另一种常见解法是将当前非零元素与最前面的零交换，一趟完成；它需要证明交换位置的状态，通常每次有效交换有两次数组写入。本次采用压缩后补零，便于理解稳定过滤，不额外实现交换版本。

## 8. 典型边界与错误

| 输入 | 修改后 | 检查目的 |
| --- | --- | --- |
| `[0,1,0,3,12]` | `[1,3,12,0,0]` | 官方示例 |
| `[0]` | `[0]` | 单个零 |
| `[7]` | `[7]` | 单个非零 |
| `[0,0,1]` | `[1,0,0]` | 连续零不能漏处理 |
| `[1,2,3]` | `[1,2,3]` | 没有零 |
| `[0,0,0]` | `[0,0,0]` | 全零 |
| `[0,-1,0,-1,2]` | `[-1,-1,2,0,0]` | 负数、重复值、稳定顺序 |
| `[1,0,2,0]` | `[1,2,0,0]` | 尾部零及交替分布 |
| `[]` | `[]` | 仓库扩展 |

常见错误包括：用大于零判断非零而漏掉负数；每轮都推进写指针；提前清零覆盖未读元素；压缩后不清理尾部；从末尾随意交换破坏顺序；以为原地修改意味着不允许任何临时变量。

## 9. 面试表达与可迁移思维

> 我先考虑遇到零就左移后续元素，但同一个数可能被反复搬动，最坏为平方级。最终结果其实是稳定的非零前缀和全零尾部，所以使用读指针扫描，写指针只在遇到非零时前进。写位置始终不超过读位置，不会覆盖未来输入；按读取顺序写入保证稳定。最后统一补零，时间 O(n)，额外空间 O(1)。

复习时回答：为什么 w 不会超过 r？为什么中间允许有重复副本？省掉补零会怎样？为什么不能从末尾任意交换？原地与稳定分别限制了什么？

这一模式可以迁移到第 27 题“移除元素”和第 26 题“删除有序数组中的重复项”：都使用写指针维护有效前缀，但它们返回有效长度，尾部通常无须补零，不能机械照搬全部步骤。
