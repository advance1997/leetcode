## 1. 题目描述

给定整数数组 `nums` 和整数目标值 `target`，找到数组中两个整数，使它们的和等于 `target`，返回它们的下标。

规则：

- 每种合法输入恰好有一个有效答案。
- 同一个元素不能使用两次。
- 返回下标的顺序不限。
- 不同位置可以具有相同数值。

数据范围：

```text
2 <= nums.length <= 10^4
-10^9 <= nums[i] <= 10^9
-10^9 <= target <= 10^9
```

示例：

| 输入数组 | target | 输出 | 解释 |
| --- | ---: | --- | --- |
| `[2, 7, 11, 15]` | 9 | `[0, 1]` | 下标 0 和 1 的元素相加等于 9 |
| `[3, 2, 4]` | 6 | `[1, 2]` | 2 + 4 = 6，不能重复使用下标 0 的 3 |
| `[3, 3]` | 6 | `[0, 1]` | 相同数值来自两个不同位置，可以配对 |

## 2. 先分析：我们真正需要找到什么？

题目要求找到两个下标 `i`、`j`，使得：

```text
i != j
nums[i] + nums[j] == target
```

返回的是下标，因此只保存数字是否出现还不够，需要能够定位它的位置。

题目没有说数组有序，不能直接使用有序数组的首尾双指针规则。可以先排序，但排序会改变位置，需要额外保存原始下标，并付出排序成本。本题有更直接的查找方式。

## 3. 暴力解法：列出所有不同位置的数对

没有优化思路时，先保证枚举完整且不重复：固定第一个位置 `i`，让第二个位置 `j` 从 `i + 1` 开始向后遍历。

```text
for i 从 0 到 n - 2：
    for j 从 i + 1 到 n - 1：
        如果 nums[i] + nums[j] == target：
            返回 [i, j]
```

为什么 `j` 不从 0 开始？

1. `j > i` 保证不会把同一个元素使用两次。
2. `(i, j)` 与 `(j, i)` 表示同一对元素，只检查一次即可。

以 `[3, 2, 4]`、`target = 6` 为例：

```text
下标：  0   1   2
数组： [3,  2,  4]

(0, 1)：3 + 2 = 5，不符合
(0, 2)：3 + 4 = 7，不符合
(1, 2)：2 + 4 = 6，返回 [1, 2]
```

任意两个不同位置都可以唯一写成 `i < j`，因此这种枚举不会漏掉答案。代码对应 `twoSumBruteForce`。

最坏需要检查 `(n - 1) + (n - 2) + ... + 1 = n(n - 1) / 2` 对元素，因此时间为 `O(n²)`，额外空间为 `O(1)`。找到答案时可提前结束，但不能据此将最坏复杂度写成线性。

## 4. 怎样从暴力解法想到优化？

### 第一步：找出耗时的动作

暴力解法固定一个数之后，还在逐一尝试其他数字。大量工作花在“寻找配对元素”上。

### 第二步：把未知的搜索对象算出来

由 `current + other = target` 可得：

```text
other = target - current
```

当前数字一旦确定，另一个数字的值就已经确定。例如目标是 6，当前数字是 4，需要的只能是 2。这个值称为“补数”。

现在的问题从“再枚举一个数”变成了“快速查找一个确定的数”。

### 第三步：选择能够同时查值和取下标的结构

哈希表支持按照键查找值。在通常平均情况下，查找和插入成本为 `O(1)`，因此可以保存：

```text
key   = 已经遍历过的数字
value = 这个数字的下标
```

这里使用 `Map<Integer, Integer>`，而不是 `Set<Integer>`，因为最终要返回下标。

### 第四步：让遍历过程本身保证下标不同

每轮只向之前出现的元素寻找配对。查找失败后，再把当前元素加入表中，供后续元素使用。

不需要同时向左、向右查找：对于任何答案，遍历到其中靠后的元素时，靠前的元素已经可以被找到。

## 5. 优化算法：单次遍历 + 哈希表

每一轮执行四步：

1. 读取当前数字 `currentValue`。
2. 计算 `complement = target - currentValue`。
3. 查询哈希表；如果有补数，返回保存的下标和当前下标。
4. 没有补数时，保存 `currentValue → currentIndex`。

关键不变量：**开始处理下标 i 时，表里只包含来自下标小于 i 的数字；每个不同数字保存一个已出现位置。**

### 为什么先查找，再存入？

对 `[3, 2, 4]`、目标 6，如果先存入下标 0 的 3，再查找补数 3，就会从表里找到刚存入的自己，错误返回 `[0, 0]`。

如果先查找：第一次查找时表为空，所以不能配对；最后由下标 1 的 2 与下标 2 的 4 组成答案。

### 重复值覆盖旧下标会漏掉答案吗？

不会。后续元素只需要找到一个数值符合要求、位置又不同的已遍历元素，同一个数字保留任意一个此前位置即可。

对于 `[3, 3]`，第二个 3 会先查到第一个 3，因此在覆盖发生之前就返回 `[0, 1]`。

## 6. 图解：让状态变化与代码对应

以下 `数字 → 下标` 表示一条映射，不表示数组指针，也不表示哈希表的内部排列顺序。

```text
nums = [3, 2, 4]，target = 6

下标：  0   1   2
数组： [3,  2,  4]
        ↑
        currentIndex = 0
需要：6 - 3 = 3
查表：{} 中没有 3
存入：{3 → 0}

下标：  0   1   2
数组： [3,  2,  4]
            ↑
            currentIndex = 1
需要：6 - 2 = 4
查表：{3 → 0} 中没有 4
存入：{3 → 0, 2 → 1}

下标：  0   1   2
数组： [3,  2,  4]
                ↑
                currentIndex = 2
需要：6 - 4 = 2
查表：找到 2 → 1
返回：[1, 2]
```

| currentIndex | currentValue | complement | 查询前 indexByValue | 执行结果 |
| ---: | ---: | ---: | --- | --- |
| 0 | 3 | 3 | `{}` | `put(3, 0)` |
| 1 | 2 | 4 | `{3 → 0}` | `put(2, 1)` |
| 2 | 4 | 2 | `{3 → 0, 2 → 1}` | `get(2)` 得到 1，返回 `[1, 2]` |

## 7. 为什么一定正确？

**初始化与保持：** 开始遍历时表为空，不变量成立。若本轮没有找到答案，只把当前元素存入表中；下一轮开始时，所有保存的位置仍然小于下一轮下标。重复数字更新下标不影响这个条件。

**返回的结果合法：** 若当前下标 i 查到补数的下标 j，则 `nums[j] = target - nums[i]`，所以两个数之和等于目标值。由不变量得 `j < i`，两个元素位置不同。

**不会遗漏：** 假设答案位置为 p、q，且 p < q。若之前未返回，遍历到 q 时，`nums[p]` 对应的数值已在表中。即使被相同数值的更近位置覆盖，保存的仍是一个小于 q、数值正确的位置，因此能够找到配对。

**能够终止：** 下标每轮加一，最多遍历 n 个元素。合法输入一定找到答案；仓库实现对无解输入在循环结束后抛出异常。

## 8. 复杂度、优势与代价

n 表示数组长度；下面的额外空间均不计固定长度的返回数组。

| 维度 | 暴力枚举 | 哈希表查找 |
| --- | --- | --- |
| 时间 | 最坏 O(n²) | 平均 O(n)，以哈希操作平均 O(1) 为前提 |
| 额外空间 | O(1) | O(n) |
| 修改输入 | 否 | 否 |
| 优势 | 直观、空间小、便于作为对照实现 | 减少配对查找的次数，适合较大数组 |
| 代价 | 元素越多，数对数量增长越快 | 需要哈希表、装箱对象及相关内存 |

哈希解法每个元素只处理一次，每轮进行常数次查询与插入，因此通常平均为 O(n)。哈希冲突会影响性能，不能把所有输入下的单次哈希操作都宣称为最坏 O(1)。

表中最多保存 O(n) 个不同数字。本实现按最多 n 个元素和负载因子 0.75 预估初始容量，减少扩容；这也意味着即使答案很早出现，首次分配仍可能预留较大的表空间。空间换时间需要同时考虑实际内存代价。

原题中加法和减法的结果均在 `[-2 × 10^9, 2 × 10^9]` 内，处于 Java `int` 的取值范围。若扩展为任意 int 输入，应重新处理溢出，并为相应边界增加测试，不能直接沿用本结论。

## 10. 边界用例与常见错误

| 场景 | nums | target | 预期结果 |
| --- | --- | ---: | --- |
| 基本示例 | `[2, 7, 11, 15]` | 9 | `[0, 1]` |
| 禁止与自己配对 | `[3, 2, 4]` | 6 | `[1, 2]` |
| 重复数字 | `[3, 3]` | 6 | `[0, 1]` |
| 包含负数 | `[-3, 4, 3, 90]` | 0 | `[0, 2]` |
| 两个零 | `[0, 4, 3, 0]` | 0 | `[0, 3]` |
| 全部为负数 | `[-1, -2, -3, -4, -5]` | -8 | `[2, 4]` |
| 先覆盖重复值再找到答案 | `[1, 1, 2, 4]` | 6 | `[2, 3]` |
| 约束极值 | `[1000000000, -1000000000]` | 0 | `[0, 1]` |

容易出错的地方：

- **先存再查：** 可能复用当前元素。保持“计算、查询、返回或存入”的顺序。
- **返回数字而非下标：** 哈希表的 value 必须记录下标。
- **用 0 判断查询失败：** 下标 0 合法。本实现不保存 null 值，因此 `get` 返回 null 才表示不存在；先判空再拆箱。
- **只用 Set：** 可以判断存在，但不能直接取出所需下标。
- **对原数组排序后直接返回位置：** 排序后的位置不是原始下标，且修改了输入。
- **认为有两层循环就一定是 O(n²)：** 应计算实际操作次数。本题暴力实现确实枚举 n(n-1)/2 对，所以是平方级。

## 11. 面试表达与复习

可以这样说明：

> 我先枚举所有不同下标的数对，能保证不漏解，但最坏要做平方级比较。固定当前数字后，配对数字其实已由 target 减去当前数字确定，所以可以用哈希表保存之前出现的数字及下标。每轮先查补数，没找到才存当前元素，保证不与自己配对。这个方法不修改输入，以线性额外空间换取通常平均线性时间。

1. 为什么只查询之前的元素，不查询后面，也不会漏解？

3. 哈希表为什么保存“数字到下标”，而不是反过来？
