## 1. 题意与边界

寻找字符串中最长的、没有重复字符的连续子串，返回长度。不是返回子串本身，也不是寻找可以跳过字符的子序列。

本次核对的 [Doocs 公开题面镜像](https://github.com/doocs/leetcode/blob/main/solution/0000-0099/0003.Longest%20Substring%20Without%20Repeating%20Characters/README.md) 标注长度范围为 `0 <= s.length <= 100000`，字符串由英文字母、数字、符号与空格组成。本次未重新访问官方页面，范围按该镜像记录，不宣称已经核对官方最新版本。

| 输入 | 输出 | 解释 |
| --- | ---: | --- |
| `abcabcbb` | 3 | `abc`、`bca`、`cab` 都可以 |
| `bbbbb` | 1 | 只能保留一个 b |
| `pwwkew` | 3 | `wke` 连续，`pwke` 不连续，因此不能返回 4 |

空字符串是原题合法输入，返回 0；大小写区分，空格与标点也参与比较，不能预先 trim 或转换大小写。

## 2. 与上一题比较：不要背同一个更新位置

| 项目 | 长度最小的子数组 | 本题 |
| --- | --- | --- |
| 窗口状态 | 区间和 | 当前字符集合 |
| 合法条件 | 和至少达到目标 | 字符没有重复 |
| 何时收缩 | 达标后，尝试更短 | 将出现重复时，必须恢复合法 |
| 何时记录 | 合法窗口收缩之前 | 冲突消除、当前字符加入之后 |
| 求什么 | 最短合法窗口 | 最长合法窗口 |

共同点是维护连续区间，左右指针只向前走。不同点是窗口是否合法以及何时更新结果，不能机械复制前一题的 while 条件。

## 3. 暴力枚举：每个起点重新扩张

固定 left，建立空集合，然后不断向右尝试加入字符。第一次遇到重复就结束这个起点的搜索，因为继续扩张不会让已经出现的重复消失。

```text
maximumLength = 0
for left 从 0 到 n-1：
    创建空字符集合
    for right 从 left 到 n-1：
        如果当前字符已存在：结束本轮
        将当前字符加入集合
        更新 right-left+1
```

对于 `abba`：从 0 开始可得到 `a`、`ab`，再读 b 时停止；从 1 开始只得到 `b`；从 2 开始可得到 `b`、`ba`；从 3 开始得到 `a`。最长长度为 2。

每个起点都枚举到其最长合法子串，所有起点被检查，所以结果完整。Java 对应 `lengthOfLongestSubstringBruteForce`。

在集合操作平均 O(1) 的前提下，时间上界 O(n²)，空间 O(min(n,C))，C 为字符集合大小。更细致的扫描上界为 O(n·min(n,C+1))，因为遇到重复后会停止；对于固定的小字符集合，实际扫描可能远低于平方级。不能把每个输入都描述为必然进行了 n² 次操作。

## 4. 优化推导：只移除失效的前缀，保留后面的有效字符

暴力从一个起点换到下一个起点时，重新创建集合、重新扫描重叠的字符。

假设当前合法窗口是 `abc`，新字符是 b：

```text
原窗口：a b c
新字符：      b
```

当前 b 与旧 b 冲突。如果从左侧依次移除 a、旧 b，剩下的 c 不需要重新扫描，新窗口就是 `cb`。

因此维护一个长期复用的集合：

1. right 指向准备加入的新字符。
2. 若集合已有该字符，就从 left 开始连续删除，直到旧的同值字符离开。
3. 加入新字符，此时窗口重新无重复。
4. 更新最长长度。

不能直接删除集合中的冲突字符而不移动 left，因为这会让集合不再对应连续区间；也不该直接清空集合，合法后缀仍有价值。

## 5. 为什么 Set 足够？

本实现加入新字符之前，旧窗口已经保证无重复，每个字符最多出现一次，所以集合可以准确表达窗口内容，不需要计数表。

顺序必须是“先消除旧冲突，再 add”。如果先 add 重复字符，Set 不会记录两个副本，之后删除旧字符会连新字符的存在状态一起丢失，必须另行修复逻辑。

如果选择先加入并维护计数的版本，则应使用 Map 或计数数组；两种表示方式都可以，但状态定义与操作顺序不能混搭。

## 6. 图解：一次重复可能要删除不止一个字符

以 `abba` 为例。L 是左端点，R 是本轮准备加入的位置，集合顺序不代表字符在字符串中的排列。

```text
下标：0 1 2 3
字符：a b b a
```

| R | 新字符 | 加入前窗口 | 删除过程 | 加入后窗口 | L | 历史最长 |
| ---: | --- | --- | --- | --- | ---: | ---: |
| 0 | a | 空 | 无 | `a` | 0 | 1 |
| 1 | b | `a` | 无 | `ab` | 0 | 2 |
| 2 | b | `ab` | 删除 a 后仍有 b；继续删除旧 b | `b` | 2 | 2 |
| 3 | a | `b` | 无 | `ba` | 2 | 2 |

第三轮详细变化：

```text
a b b a     集合 {a,b}，准备加入下标2的 b
L   R

a b b a     删除 a，集合 {b}，冲突仍在
  L R

a b b a     删除旧 b，集合 {}，冲突解除
    L/R

a b b a     加入新 b，集合 {b}，合法长度1
    L/R
```

因此 while 不能改成只执行一次的 if，否则会把仍有重复的 `bb` 当作合法窗口。

再看 `pwwkew`：

| R | 新字符 | 操作后的合法窗口 | 历史最长 |
| ---: | --- | --- | ---: |
| 0 | p | `p` | 1 |
| 1 | w | `pw` | 2 |
| 2 | w | 删除 p、旧 w 后得到 `w` | 2 |
| 3 | k | `wk` | 2 |
| 4 | e | `wke` | 3 |
| 5 | w | 删除旧 w 后得到 `kew` | 3 |

## 7. 正确性与终止

加入当前字符前，集合精确表示 `[left,right)`，且该区间无重复。

如果新字符不存在，加入后仍无重复；如果存在，则从左侧删除到旧同值位置离开为止。原窗口其他字符没有重复，删除只会保留无重复后缀，因此再加入当前字符后仍合法。

为什么恢复后的窗口是以当前 right 结尾的最长合法窗口？若旧同值字符位于 p，任何起点不超过 p 的窗口都会同时包含两个同值字符，必须至少移动到 p+1。本算法恰好移到该位置，没有多删。若本轮无冲突，left 保持不变，之前排除的更早起点仍包含此前已有的重复，继续扩张不会修复那些重复。

因此，每个右端点的最长合法窗口都被记录，对这些长度取最大值就得到全局最优。left、right 不回退，每轮收缩会删除至少一个窗口内字符，旧冲突必然能够被移除，整体能够终止。

## 8. 复杂度、收益与代价

令 n 为 Java 字符串长度，C 为比较单位的字符集合大小。

| 方法 | 时间上界，哈希操作按平均 O(1) | 辅助空间 | 特点 |
| --- | --- | --- | --- |
| 每个起点重新扩张 | O(n²) | O(min(n,C)) | 直观，但重复维护重叠窗口 |
| 滑动窗口复用集合 | O(n) | O(min(n,C)) | 每个位置最多加入、移除各一次 |

for 与 while 嵌套不意味着平方级：right 总共走 n 步，left 也至多走 n 步，集合操作总数为 O(n)。HashSet 的平均常数时间是假设，不将所有输入下每次操作都宣称为最坏 O(1)。

集合按当前窗口保存字符，不为每个右端创建子串副本；答案只需要长度，避免 substring 的复制成本。集合从容量 16 开始随需要扩容，避免直接按整串长度预分配大量空间，但可能有扩容和 Character 装箱开销。

## 9. 可选变式：记录字符上一次出现的位置

可以用映射保存每个字符最近的下标，遇到当前字符时直接设置：

```text
left = max(left, 上次出现下标 + 1)
```

之后更新最近下标并计算长度。必须使用 max，避免左端回退。反例仍是 `abba`：处理最后的 a 时，它上次出现于 0，但当前 left 已为 2，不能退回 1，否则会错误包含两个 b。

这个版本可减少逐个删除的操作，但不改变平均 O(n) 的复杂度量级。本次以集合收缩版建立窗口基础，最近位置版本仅讨论思路，未实现或验证。

## 10. 字符语义与接口

[Java 实现](./LongestSubstringWithoutRepeatingCharacters.java) 提供 `lengthOfLongestSubstringBruteForce` 和推荐方法 `lengthOfLongestSubstring`。null 抛出 IllegalArgumentException，空串返回 0，不改变大小写或空格，不校验长度上限。

两种方法使用 charAt 和 Character，以 UTF-16 代码单元为单位。不要将其直接宣称为按完整 Unicode 码点或用户感知字符统计的通用算法。例如某些 emoji 由两个 char 表示；若需求扩展到 Unicode，需先确定码点或字素簇语义，再调整遍历、位置和长度单位。

## 11. 边界与常见错误

| 输入 | 预期长度 | 检查目的 |
| --- | ---: | --- |
| `abcabcbb` | 3 | 官方示例 |
| `bbbbb` | 1 | 全重复 |
| `pwwkew` | 3 | 子串不能跳位置 |
| 空串 | 0 | 合法空输入 |
| `a` | 1 | 单字符 |
| 一个空格 | 1 | 空格参与计算 |
| 两个空格 | 1 | 空格也会重复 |
| `abba` | 2 | 连续收缩、禁止回退 |
| `dvdf` | 3 | 保留有效后缀，不能清空集合 |
| `Aa` | 2 | 大小写不同 |
| `a1! a` | 4 | 数字、符号、空格混合 |
| `tmmzuxt` | 5 | 重复出现在不同位置 |

常见错误：重复时直接清空窗口；用 if 只删除一次；删除集合里的冲突值却不推进 left；在非法窗口状态下更新最大值；误用全局出现过的字符集合；把子序列长度当作子串长度；只支持小写字母却访问其他字符。

提交平台时复制推荐方法、validateInput、INITIAL_SET_CAPACITY 和 Set/HashSet 导入到 Solution 类，移除包声明及工具类构造方法。

## 12. 面试表达与专题安排

> 我先从每个起点向右扩张直到重复，但相邻起点重复扫描很多。改用左右窗口和字符集合，加入新字符前如果集合已有它，就从左侧删除到旧同值字符离开，再加入当前字符。这个窗口是以当前右端结尾的最长合法窗口，取所有右端的最大长度即可。两个指针各自只前进，哈希操作按平均常数时间计算时，总时间 O(n)，空间由窗口中的不同字符数决定。

复习时手算 `abba` 和 `dvdf`，解释为何不能清空集合、为何一定用 while、为何答案在恢复合法后更新。

本题继续滑动窗口专题，从整数和状态推进到字符集合状态。下一阶段可学习固定窗口中的字符频次匹配，再考虑更复杂的覆盖条件，保持同类题由简到难。
