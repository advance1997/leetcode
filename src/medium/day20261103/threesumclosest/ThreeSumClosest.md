## 1. 题意、约束与返回值

从 nums 中三个不同下标选取整数，使三数之和与 target 最接近，返回这个和。原题保证每组输入恰好有一个解。

```text
3 <= nums.length <= 1000
-1000 <= nums[i] <= 1000
-10000 <= target <= 10000
```

官方示例：

- `nums = [-1,2,1,-4]，target = 1`，返回 2，因为 `-1+2+1=2`，距离目标为 1。
- `nums = [0,0,0]，target = 1`，返回 0。

本次通过 [Doocs 公开题面镜像](https://github.com/doocs/leetcode/blob/main/solution/0000-0099/0016.3Sum%20Closest/README.md) 核对题意、难度和约束，没有重新访问官方页面，不标注未经核实的公司频率。

这里返回的是**三数和**，不是三元组、下标，也不是最小差值。相同数值可以来自不同位置；不存在精确匹配也必须返回实际可构成的最优和。

## 2. 与上一题比较：哪些能复用，哪些不能？

| 维度 | 三数之和 | 最接近的三数之和 |
| --- | --- | --- |
| 目标 | 等于零 | 与任意 target 的绝对差最小 |
| 输出 | 所有不重复三元组 | 一个最接近的和 |
| 每轮更新 | 仅命中时记录三元组 | 每个候选都可能改善答案 |
| 精确命中 | 继续找其他答案 | 可以立即返回 |
| 去重 | 必须避免重复输出 | 不输出列表，重复计算不会造成重复答案 |
| 首数为正 | 可以结束零和搜索 | 不能直接结束，目标可能也是正数 |

本题沿用“固定一个数，再用双指针”的结构，但新增的是维护最优差值、真实候选初始化，以及证明候选排除仍适用于距离目标的最小化。

## 3. 暴力枚举：明确我们优化的目标

枚举 `first < second < third`，计算：

```text
sum = nums[first] + nums[second] + nums[third]
distance = abs(sum - target)
```

用一个真实三数和初始化 closestSum，然后逐个比较，保留差值更小的候选。

```text
closestSum = nums[0] + nums[1] + nums[2]
for first：
    for second 从 first+1 开始：
        for third 从 second+1 开始：
            计算 currentSum
            若 currentSum == target：返回 target
            若更接近：更新 closestSum
返回 closestSum
```

原题保证唯一解。为了明确仓库在等距扩展输入下的行为，两种方法额外约定：不同的和同样接近时，选择较小的和。例如 `[-2,0,2,4]`、目标 1，可以得到和 0 与 2，仓库返回 0。这不是原题额外要求。

三个不同下标的组合恰好枚举一次，因此不会遗漏合法候选。最坏枚举 `C(n,3)` 个组合，时间 O(n³)，额外空间 O(1)，不需要排序或复制。

为什么不能把 closestSum 初始化为 target？因为 target 可能无法由任何三个元素构成，却会以差值零阻止所有真实候选更新。例如 `[0,0,0]`、target=1，错误初始化就可能返回不存在的和 1。

## 4. 怎样优化：把剩余两数的搜索变成单调扫描

固定第一个数 a，剩下两数应尽量接近 `target-a`。无序数组中无法仅凭和的大小判断下一步该移动哪里，所以先排序。

本实现复制数组再排序，保留原输入。固定 first 后：

```text
left = first + 1
right = n - 1
```

每一轮按以下顺序执行：

1. 计算当前和。
2. 若等于 target，立即返回，因为绝对差不能小于零。
3. 比较绝对差，必要时更新 closestSum。
4. 当前和小于 target 时 left 加一；大于 target 时 right 减一。

不能先移动再计算，否则可能漏掉当前最优候选。本题没有必要输出全部组合，基础实现不加入去重逻辑，重复值最多增加重复计算，不影响正确性或 O(n²) 上界。

## 5. 为什么移动不会跳过更接近的答案？

假设当前 `s = a + sorted[left] + sorted[right] < target`。

保留 left，换任何更小的右端 k，都有：

```text
a + sorted[left] + sorted[k] <= s < target
```

这些和全部在目标左侧，而且不大于 s，因此它们到目标的距离不小于 `target-s`。当前 s 已经比较过，保留 left 的其他组合不会更好，可以安全排除 left。

对 `s > target`，保留 right，换更大的左端 k，只会使和更大且继续位于目标右侧，距离不会减小，因此可以排除 right。

这里的理由不是“移动后一定更接近”。移动后可能跨过 target，差值反而增大。算法只保证被排除的候选不可能比当前已评估的候选更好，所以必须保留全局最优值。

等距时选较小和也不会破坏上述证明：被排除的候选都在目标同一侧；若距离相同，它们的和只能与当前和相同，不会产生一个更值得保留的不同和。

## 6. 图解与逐步执行

官方输入排序后：

```text
原数组：[-1, 2, 1, -4]
排序后：[-4,-1, 1,  2]
下标：    0  1  2   3
目标：1

初始真实候选 = -4 + -1 + 1 = -4，差值 5

[-4, -1, 1, 2]
  F   L     R     当前和 -3，差值 4 → 更新为 -3，L 右移

[-4, -1, 1, 2]
  F      L  R     当前和 -1，差值 2 → 更新为 -1，L 右移后相遇

[-4, -1, 1, 2]
      F  L  R     当前和 2，差值 1 → 更新为 2，R 左移后相遇
```

F 为固定下标，L、R 为双指针。完整状态表：

| first | left | right | 当前和 | 与 1 的距离 | closestSum 更新后 | 下一步 |
| ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 0 | 1 | 3 | -3 | 4 | -3 | left → 2 |
| 0 | 2 | 3 | -1 | 2 | -1 | left → 3 |
| 1 | 2 | 3 | 2 | 1 | 2 | right → 2 |

最后返回 2，而不是距离 1。

数轴也能帮助理解绝对差：

```text
候选： -4    -3          -1           1     2
       距离5  距离4       距离2        目标  距离1
```

## 7. 正确性与终止

合法性：closestSum 初始化自三个不同位置，之后也只用 `first < left < right` 的真实候选更新，返回值始终可构成。

循环不变量：closestSum 是已经评估的候选中最优的和；对于当前固定首数，已排除的候选不会优于某个已评估候选。每轮先比较当前候选，再根据有序性安全排除一侧，因此不变量保持。

完整性：固定首数对应的所有剩余候选，最终要么被评估，要么被证明不可能改善当前已知结果。外层遍历所有可能的首位置，所以不会遗漏更优和。

精确命中时距离为零，已达到理论最优，可以结束所有循环。否则，内层每轮至少有一个指针向内移动，外层也单调前进，因此算法必然终止。

## 8. 复杂度、收益与代价

令 n 为数组长度。

| 解法 | 最坏时间 | 额外空间 | 修改输入 | 取舍 |
| --- | --- | --- | --- | --- |
| 三重枚举 | O(n³) | O(1) | 否 | 容易理解，适合小输入对照 |
| 排序副本 + 双指针 | O(n²) | O(n) | 否 | 少一层枚举，但需要排序与候选排除证明 |

固定首数后，左右指针只向内移动，合计 O(n) 次；最多 O(n) 个首位置，所以总扫描时间 O(n²)。排序不会增加总的平方级上界。

本实现有数组副本，不能写成 O(1) 辅助空间。排序内部空间依具体 JDK 实现而定，本实现总体按 O(n) 计；返回一个 int，不存在随答案数量增长的输出集合。

原题三数和在 [-3000,3000]，目标在 [-10000,10000]，差值绝对值至多 13000，int 安全。扩展到任意 int 输入时，既要考虑三数求和溢出，也要考虑减法和 `Math.abs(Integer.MIN_VALUE)` 的问题，应在运算前提升为 long，并重新定义返回类型。

null、空数组、长度一或二均抛出 IllegalArgumentException。与上一题不足三时返回空列表不同，本题必须返回一个实际三数和，不应返回伪造的默认值。数值范围、长度上限、答案唯一性不逐项校验，由调用者遵守；等距选择较小和是已说明的仓库扩展。

| nums | target | 预期 | 目的 |
| --- | ---: | ---: | --- |
| `[-1,2,1,-4]` | 1 | 2 | 官方示例 |
| `[0,0,0]` | 1 | 0 | 无精确解 |
| `[-1,0,1,2]` | 0 | 0 | 精确命中 |

错误示范：返回最小差而不是和；初始化为不可构成的 0 或 target；直接比较有符号差值；照搬三数之和的“首数为正就结束”；命中后仍寻找其他三元组；为了去重先删除数组里的重复数字。

## 10. 面试复述与专题迁移

> 我先枚举所有三数和，按与目标的绝对差维护最优值。排序后固定首数，剩下两数用相向双指针搜索。当前和偏小时，保留左端并换更小右端只会更远，所以记录当前结果后可排除左端；偏大时对称处理。若精确命中，差为零立即返回。最坏时间 O(n²)，本实现复制输入用于排序，辅助空间 O(n)。

复习时回答：初始化为什么必须是真实候选？和小于目标时，为什么可以排除当前左端的所有剩余配对？指针移动后距离一定减小吗？首数大于零时为什么不能直接 break？等距行为是原题要求还是仓库扩展？

本题继续双指针专题，在三数之和的基础上练习“从精确匹配切换为最优值维护”。后续可进入四数之和，学习增加固定层、去重和溢出处理，而不是立即切换到无关算法类别。
