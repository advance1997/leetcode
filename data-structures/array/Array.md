# 数组（Array）：从下标访问到元素搬移

[返回数据结构导航](../README.md)

本节是数据结构基础的第一课。目标是能解释数组为什么适合随机访问、为什么中间插入需要移动元素，以及 Java 数组与 `ArrayList` 的区别。

## 1. 数组是什么

数组把一组具有相同组件类型的元素组织成有顺序、可按整数下标访问的序列。Java 数组对象创建后长度固定，可以修改元素，但不能改变该对象的长度。

```text
int[] numbers = {10, 20, 30, 40};

下标：       0       1       2       3
         ┌───────┬───────┬───────┬───────┐
元素值： │  10   │  20   │  30   │  40   │
         └───────┴───────┴───────┴───────┘
长度：4；合法下标：0～3；numbers[2] 的值为 30。
```

“有顺序”表示位置有先后，不表示元素已经按数值排序。重复值也允许存在，下标仍能区分各个位置。

Java 基本类型数组如 `int[]` 保存基本类型值；引用类型数组如 `String[]` 保存引用，引用指向的对象不必相邻。不能把一组对象引用误认为所有对象本体连续排列。

## 2. 为什么下标访问是 O(1)

在经典数组存储模型中，每个元素槽位大小相同，可用如下公式定位：

```text
第 i 个槽位的位置 = 首槽位位置 + i × 槽位宽度
```

例如仅作模型演示，首地址为 1000、槽位宽度为 4，则下标 3 的位置为 `1000+3×4=1012`。无需从下标 0 逐个走到 3，因此按下标读取或覆盖写入为 O(1)。

这是算法分析的抽象模型。Java 不向程序暴露普通数组的内存地址，具体对象头、对齐与布局由 JVM 实现决定，不能从这个公式推断某个 Java 对象的实际地址。常见实现中数组槽位紧凑、顺序扫描有利于缓存局部性；这不是所有运行环境下的性能承诺。

**已知下标读取**与**按值查找下标**不同：问“下标 3 是什么”可以直接读取；问“30 在哪里”对无序数组通常需要逐项比较。

## 3. 长度、容量和有效元素个数

Java 原生数组只有固定的 `length` 属性。为了用一个数组维护可增删的逻辑序列，可以另外维护 `size`：

```text
底层数组： [10, 20, 30, 0, 0]
有效部分： └────────┘
size = 3                 有效元素数量，由程序维护
capacity = array.length = 5   可用槽位数量
```

后两个 0 是尚未使用槽位的默认值，并不意味着“0 不能作为有效数据”。哪些元素有效由 `size` 决定。

必须保持 `0 <= size <= array.length`。读取有效元素的下标范围是 `[0,size)`；插入位置允许 `[0,size]`，其中 `size` 表示末尾追加。访问数组本身还必须满足 `[0,array.length)`，这两套边界不能混淆。

## 4. 核心操作与图解

### 4.1 访问、遍历与查找

- `numbers[index]`：知道下标，读取或覆盖一个槽位，O(1)。覆盖不增加元素个数。
- 遍历：顺序访问 n 个有效元素，O(n)。
- 无序查找：最坏需要比较 n 个元素，O(n)，即使只需要一个结果也可能最后才找到。
- 有序数组二分查找：每次排除约一半候选位置，O(log n)。必须已经按相同规则排序。若只为一次查找先排序，排序成本通常会超过直接扫描，不能忽略预处理。

### 4.2 保持顺序的插入：先腾出位置

有足够容量时，向 `[10,20,30]` 的下标 1 插入 15：

```text
初始： [10, 20, 30, 0, 0]  size=3
搬移： [10, 20, 30,30, 0]  原下标 2 → 3
搬移： [10, 20, 20,30, 0]  原下标 1 → 2
写入： [10, 15, 20,30, 0]  下标 1 写入 15，size=4
有效： [10, 15, 20,30]
```

搬移过程中的重复值是暂时状态。必须从右向左复制，避免先覆盖后面仍需读取的元素。向下标 i 插入，需要移动 `n-i` 个元素，最坏为 O(n)；容量充足的末尾追加不搬移，O(1)。

如果容量不足，原生数组不能原地变长，需要创建更大的数组并复制有效元素。新旧数组是不同对象，其他持有旧数组引用的变量不会自动指向新数组。

### 4.3 保持顺序的删除：左移填补空位

从 `[10,15,20,30]` 删除下标 1：

```text
初始： [10, 15, 20,30, 0]  size=4
搬移： [10, 20, 20,30, 0]  原下标 2 → 1
搬移： [10, 20, 30,30, 0]  原下标 3 → 2
收尾： [10, 20, 30, 0, 0]  size=3，清理原末尾槽位
```

删除后从左向右搬移，移动 `n-i-1` 个元素。把 `int[]` 的废弃槽位置 0 是便于阅读的约定，逻辑删除由 `size` 减少体现；引用数组应把废弃引用设为 `null`，避免容器继续保留不再使用的对象。

如果业务完全不要求保持顺序，可以用末尾元素覆盖被删位置，再减少 size，已知下标时能 O(1) 删除。但这改变顺序，不能用在必须保序的问题中；若还需要按值定位，查找成本另算。

## 5. Java 示例：完整演示插入、删除与扩容

下面是可单独保存为 `ArrayExample.java` 的教学示例，包名为 `learning.datastructures.array`。本节先把示例放在文档内，不额外建立手写容器类。固定输入用于追踪操作；若封装为通用接口，还需检查 null、size、容量和下标。

```java
package learning.datastructures.array;

import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

/**
 * 数组基础示例：展示固定容量内的保序插入、删除、复制扩容及集合转换。
 *
 * <p>使用预先确定的合法输入；原生数组操作会修改局部数组内容。
 * 插入、删除最坏时间 O(n)，扩容复制时间和额外空间均为 O(n)。
 * 本类是数据结构教学示例，不对应某一道 LeetCode 题目。</p>
 */
public final class ArrayExample {

    /**
     * 禁止实例化示例工具类。
     */
    private ArrayExample() {
    }

    /**
     * 运行示例并输出每一步的有效序列。
     *
     * @param args 命令行参数，本示例不使用
     */
    public static void main(String[] args) {
        // 容量为 5，只有前 3 个元素有效，0 不是空槽位的判断依据。
        int[] numbers = {10, 20, 30, 0, 0};
        int size = 3;
        int insertIndex = 1;

        // 从右向左移动，为插入位置腾出空间，避免覆盖尚未复制的数据。
        for (int index = size; index > insertIndex; index--) {
            numbers[index] = numbers[index - 1];
        }
        numbers[insertIndex] = 15;
        size++;
        System.out.println(Arrays.toString(Arrays.copyOf(numbers, size)));

        // 删除下标 1，从左向右填补空位，保持其余元素的原有顺序。
        int removeIndex = 1;
        for (int index = removeIndex; index < size - 1; index++) {
            numbers[index] = numbers[index + 1];
        }
        size--;
        numbers[size] = 0;
        System.out.println(Arrays.toString(Arrays.copyOf(numbers, size)));

        // 显式创建更长的数组；旧数组对象仍然保持原长度，size 不变。
        int[] oldNumbers = numbers;
        numbers = Arrays.copyOf(numbers, numbers.length * 2);
        System.out.println(oldNumbers.length + " -> " + numbers.length);

        // 用包装类型集合演示按下标删除与按值删除的区别。
        List<Integer> values = new ArrayList<>(Arrays.asList(10, 20, 30));
        values.remove(1);
        values.remove(Integer.valueOf(30));
        System.out.println(values);

        // int[] 会被视为一个对象元素，asList 不会把它逐项装箱。
        int[] primitiveValues = {1, 2, 3};
        List<int[]> wrappedArray = Arrays.asList(primitiveValues);
        System.out.println(wrappedArray.size());
    }
}
```

预期输出：

```text
[10, 15, 20, 30]
[10, 20, 30]
5 -> 10
[10]
1
```

示例为显示有效区间使用了 `Arrays.copyOf`，这些打印辅助操作分配 O(n) 临时空间。不要把演示程序整体的空间开销，与容量充足时插入、删除循环本身的 O(1) 辅助空间混为一谈。

## 6. 原生数组与 ArrayList

| 对比项 | Java 数组 | `ArrayList<E>` |
| --- | --- | --- |
| 长度或元素数 | `array.length`，创建后固定 | `list.size()`，随增删变化 |
| 元素类型 | 支持基本类型与引用类型 | 泛型参数使用引用类型，如 `Integer` |
| 下标访问 | `array[i]` | `get(i)`、`set(i, value)` |
| 扩容 | 自己分配新数组并复制 | 内部管理容量，必要时扩容 |
| 中间插入、删除 | 自己搬移并维护有效长度 | API 代为搬移，最坏仍为 O(n) |
| 适用情况 | 规模明确、数值计算、算法输入 | 需要方便地维护可变长序列 |

`new ArrayList<>(10)` 只设置初始容量，size 仍为 0，不能马上调用 `get(0)` 或 `set(0, value)`；要先 `add` 元素。`set` 替换已有元素，`add` 才增加元素个数。

动态数组通常按比例增长容量。一次扩容复制 n 个元素需要 O(n)，但连续追加很多元素时，几何增长使累计复制量保持在线性量级，因此追加的**均摊**时间是 O(1)。这不意味着每次追加的最坏时间都是 O(1)。具体增长倍率属于实现细节，不应当作 Java 集合接口的固定保证。示例用两倍容量仅用于说明复制原理。

## 7. 操作复杂度汇总

令 n 为有效元素数量；下表插入和删除均以保持顺序为前提，空间指辅助空间。

| 操作 | 时间 | 辅助空间 | 条件 |
| --- | --- | --- | --- |
| 按下标读取或覆盖 | O(1) | O(1) | 已知合法下标 |
| 遍历、无序按值查找 | O(n) | O(1) | 最坏扫描所有有效元素 |
| 二分查找 | O(log n) | O(1) | 已排序，采用迭代实现 |
| 中间或头部插入 | O(n) | O(1) | 容量充足，搬移元素 |
| 中间或头部删除 | O(n) | O(1) | 不额外缩容 |
| 尾部追加、尾部删除 | O(1) | O(1) | 有容量且无扩容、缩容 |
| 复制到按比例扩大的数组 | O(n) | O(n) | 原容量与有效数量同阶 |
| 动态数组连续追加 | 均摊 O(1)，单次最坏 O(n) | 扩容时 O(n) | 几何增长，累计分析 |

优势是下标访问快、结构简单、扫描方便。代价是原生数组定长、保序的中间修改需要搬移，以及扩容时的复制和额外容量。链表不需要整体搬移来修改节点连接，但必须考虑定位节点、获取前驱和额外引用空间；不能简单宣称“链表插入总是比数组快”。

## 8. Java 常见误区

| 情况 | 正确认识 |
| --- | --- |
| 空数组与 null | `new int[0]` 是长度为 0 的对象；null 没有数组对象，读取 length 会抛异常 |
| 默认值 | `int[]` 元素默认 0，`boolean[]` 默认 false，引用数组默认 null |
| 数组越界 | 合法下标为 `[0,length)`；下标等于 length 也越界 |
| 数组赋值 `b = a` | 两个变量指向同一数组，修改 b 的元素也会反映在 a 中 |
| `clone`、`Arrays.copyOf` | 创建新数组；引用数组仍复制引用，是浅复制，不递归复制对象 |
| 比较数组内容 | `a.equals(b)` 不做逐项比较；一维内容比较用 `Arrays.equals`，嵌套数组可用 `Arrays.deepEquals` |
| 打印数组 | 用 `Arrays.toString`；嵌套数组可用 `Arrays.deepToString` |
| `Arrays.asList(int[])` | 得到仅含一个 int[] 元素的列表，长度为 1，而不是整数列表 |
| `Arrays.asList(Integer[])` | 得到受原数组支持的固定大小列表，可 set；add、remove 不支持 |
| `List<Integer>.remove(1)` | 删除下标 1；按值删除整数 1 使用 `remove(Integer.valueOf(1))` |
| 二维数组 | 是数组的数组，各行可长短不同，甚至为 null，不能假设是连续矩形内存 |
| 下标安全但求和溢出 | 下标合法不代表值的计算安全；根据值范围与数量判断是否使用 long |

## 10. 面试复述与自测

> 数组通过下标定位槽位，读取和覆盖是 O(1)。无序按值查找最坏仍为 O(n)。如果要在中间保序插入或删除，就需要移动后面的元素，所以最坏 O(n)。Java 原生数组长度固定，动态数组通过申请更大数组并复制来扩容。动态数组追加通常均摊 O(1)，但触发扩容的单次操作可能 O(n)。我会根据访问模式、是否保序和容量变化选择结构。

自测题（尚未代表学习者完成）：

1. `[4,8,12,0,0]`，size=3，向下标 0 插入 2，每一步移动什么？为什么反向移动？
2. 删除同一有效序列的最后一个元素，需要搬移几个元素？
3. 数组中有很多 0，怎样区分有效数据与剩余容量？
4. 数组已经有下标，为什么查找某个值仍可能 O(n)？
5. `ArrayList` 的容量是 10，size 为 0，此时 `set(0, 5)` 能否成功？

参考要点：插入依次移动 12、8、4 再写入 2；删尾无需搬移；有效边界由 size 定义；值没有直接给出下标；set 不能访问不存在的逻辑元素，应先 add。
