## 1. 从数组的限制想到链表

数组可以通过下标快速定位，但在中间保序插入元素，需要把后续元素搬开。另一种组织方法是让每个元素自己记录“下一个元素在哪里”，逻辑顺序由连接关系决定。

```text
head → [10 | next] → [20 | next] → [30 | null]
         节点 A         节点 B         节点 C
```

方框表示节点对象，左半部分保存数据，右半部分保存后继引用；箭头表示引用关系，不是内存里的连续位置。节点对象不要求相邻。Java 中使用对象引用连接节点，不需要手动计算或释放内存地址。

访问下标 2 必须从表头沿 next 走两步，不能根据 `head + 2 × 节点大小` 直接定位。因此单链表按下标访问最坏 O(n)。同值节点仍是不同节点，值相等不能代替对象身份判断。

## 2. 单向、双向、循环链表

| 结构 | 示意 | 主要特点与代价 |
| --- | --- | --- |
| 单链表 | `A → B → C → null` | 每节点一个后继引用；不能直接回到前驱 |
| 双向链表 | `null ← A ⇄ B ⇄ C → null` | 额外保存前驱；已知节点时可直接改两侧连接，但维护更复杂 |
| 循环链表 | `A → B → C → A` | 最后一个节点连回起点；遍历不能用“遇到 null”作为唯一终止条件 |

本节实现**带哨兵的非循环单链表**，只保存 int 值；双向和循环结构先理解模型，不把多种实现混在一个入门类里。Java 标准库 `LinkedList<E>` 是双向链表，与这里的单链表不同。

## 3. 为什么使用哨兵节点

没有哨兵时，删除第一个节点需要修改 head，删除其他节点则修改前驱的 next，容易形成特殊分支。增加一个不代表业务数据的固定节点，可以统一处理：

```text
空表： sentinel → null                          size=0
非空： sentinel → [10] → [20] → [30] → null     size=3
                  ↑ 第一个有效节点
```

实现中哨兵的值为 0，但这个值不参与数据操作，真实数据仍允许 0。哨兵也不计入 size，不参与反转。第 0 个有效节点的前驱就是哨兵。

必须始终维护：

- size 等于有效节点数；size=0 时哨兵后继为 null。
- 有效节点沿 next 可达且没有环，末节点 next 为 null。
- 节点只由内部操作管理，外部不能任意修改 next。

本实现没有尾指针，因此尾插仍需遍历。增加尾指针可以将尾插降为 O(1)，但插入、删除最后一个节点和反转时都需要同步维护它。先掌握最小状态的正确性，再扩展更合适。

## 4. Java 接口与边界约定

实现包：`learning.datastructures.linkedlist`；类：`SinglyLinkedList`。代码位于 `src/learning/datastructures/linkedlist/`，不使用难度或日期包；历史 `src/datastructure` 不变。

| 方法 | 含义 | 边界约定 |
| --- | --- | --- |
| `size()` | 返回有效节点数 | 空表为 0 |
| `get(index)` | 读取指定下标的值 | `0 <= index < size` |
| `insert(index, value)` | 在该位置插入值 | `0 <= index <= size`；size 表示尾插 |
| `remove(index)` | 删除指定位置，返回被删值 | `0 <= index < size` |
| `indexOf(value)` | 找首个相等值的下标 | 无匹配返回 -1 |
| `reverse()` | 原地反转连接 | 空表和单节点也适用 |
| `toArray()` | 返回顺序快照 | 新数组与链表独立 |

所有 int 值都可保存，允许重复。非法下标抛出 `IndexOutOfBoundsException`，验证在修改前完成；当节点数达到 `Integer.MAX_VALUE` 时，插入抛出 `IllegalStateException`，避免计数溢出。实际容量还受可用内存约束。类不支持并发修改，不提供泛型、迭代器等生产容器能力。

## 5. 插入图解：先接后面，再接前面

初始序列 `[10,30]`，在下标 1 插入 20。先从哨兵前进一次，找到前驱 previous，即值为 10 的节点。

```text
修改前： previous → [10] ─────────→ [30] → null
         inserted → [20 | null]

第一步： inserted.next = previous.next
         previous → [10] ─────────→ [30] → null
         inserted → [20] ─────────↗

第二步： previous.next = inserted
         sentinel → [10] → [20] → [30] → null
```

最后 size 加一。新增节点先接上原后继，旧后缀仍可达；再替换前驱的连接，其他节点无需搬移。

若先写 `previous.next = inserted`，再写 `inserted.next = previous.next`，后一句会把新节点连向自身，形成自环并丢失原后缀。因此两句不能随意交换；另一种正确写法需要提前单独保存原后继。

头插时 previous 是哨兵；尾插时原后继为 null，两种情况都复用相同逻辑。

## 6. 删除图解：让前驱绕过目标

从 `[10,20,30]` 删除下标 1：

```text
修改前： sentinel → [10] → [20] → [30] → null
                    prev   removed

核心：   previous.next = removed.next
修改后： sentinel → [10] ───────→ [30] → null
                           [20] → null  （断开后继）
```

最后 size 减一并返回 20。被删除节点不再属于链表，实际内存回收由垃圾收集器决定，不代表执行 remove 就立即释放内存。

已知前驱时改连接只需 O(1)；通过下标删除仍要先找前驱，最坏 O(n)。即使保存尾指针，单链表删除尾节点仍通常需要查找其前驱。

仅给定待删节点的引用，并不总能 O(1) 正常删除它。复制后继值的特殊技巧不适用于尾节点，也改变节点身份对应的数据；本实现的值字段不可变，不采用这种技巧。

## 7. 反转图解：保存未处理部分的入口

最直观的替代方案是收集所有值，再重建逆序链表，时间 O(n)，但要 O(n) 额外存储或新节点。我们已有节点，只需改变连接方向，三个引用就足够。

每轮处理一个节点：

```java
Node next = current.next;  // 保存尚未处理后缀的入口
current.next = previous;  // 将当前节点连接到已反转前缀
previous = current;       // 扩大已反转部分
current = next;           // 继续处理原来的后继
```

该片段对应类内部的 `reverse()`，Node 是私有嵌套类；完整可运行程序以 Java 文件为准。

对 `[10,20,30]` 的完整追踪：

| 时刻 | previous 指向的已反转部分 | current 指向的待处理部分 |
| --- | --- | --- |
| 初始化 | null | `10 → 20 → 30 → null` |
| 处理 10 后 | `10 → null` | `20 → 30 → null` |
| 处理 20 后 | `20 → 10 → null` | `30 → null` |
| 处理 30 后 | `30 → 20 → 10 → null` | null |

循环结束后让 `sentinel.next = previous`。反转过程中用局部引用管理两段，结束时恢复哨兵指向新表头。不能在尚未完成时把哨兵后继当作完整链表入口；类不支持并发观察或修改。

**为什么正确：**每轮开始时，previous 保存原序列已处理前缀的逆序，current 保存剩余后缀，二者覆盖全部原节点且不重叠。先存 next，保证改线不会丢失后缀；将当前节点加入逆序前缀后不变量继续成立。每轮减少一个待处理节点，n 轮后后缀为空，previous 就是全部节点的逆序。空表循环不执行，最终仍指向 null，size 始终不变。

## 8. 复杂度与数组对比

令 n 为有效节点数，以下均指本节不含尾指针的实现。除快照外，操作的辅助空间均为 O(1)，插入额外创建一个 O(1) 节点；链表总存储为 O(n)。

| 操作 | 单链表实现 | 数组或动态数组 | 原因与前提 |
| --- | --- | --- | --- |
| 按下标读取 | 最坏 O(n) | O(1) | 链表需沿引用前进 |
| 无序按值查找 | 最坏 O(n) | 最坏 O(n) | 都可能逐个比较 |
| 头插、头删 | O(1) | 保序时 O(n) | 数组通常需搬移后续元素 |
| 按下标中间插删 | 最坏 O(n) | 最坏 O(n) | 链表定位，数组搬移，瓶颈不同 |
| 尾插 | O(n) | 有容量时 O(1)，动态扩容时 O(n) | 本实现未保存尾指针 |
| 尾删 | O(n) | 无缩容时 O(1) | 单链表需要找到前驱 |
| 原地反转 | O(n) | O(n) | 链表改连接，数组交换值 |
| 获取独立数组快照 | O(n) 时间、O(n) 返回空间 | 复制同样 O(n) | 必须产生 n 个结果值 |

链表优势是可以局部修改连接，无需搬移整个后缀，也无需整体扩容复制；代价是每节点额外引用和对象开销、定位慢、通常不如数组顺序扫描有利于缓存。不能仅凭“频繁插入”选链表，还要问插入位置如何获得。

## 10. Java 标准库的选择与常见误区

`java.util.LinkedList<E>` 实现 List 与 Deque，底层为双向链表。按下标操作会先定位，最坏仍为 O(n)。不要用 `for (i...) get(i)` 遍历整个 LinkedList，否则总时间可能 O(n²)；顺序迭代更合适。

需要栈或队列时也应考虑 `ArrayDeque`，不能因为 LinkedList 实现 Deque 就认为它总是最佳。具体选择将在后续栈、队列专题说明。

| 易错点 | 原因或正确做法 |
| --- | --- |
| 把哨兵计入 size | 哨兵只统一边界，不是有效数据 |
| 插入只允许 index < size | 会禁止尾插；插入允许 index == size |
| 空表调用 get(0) | 没有有效节点，应抛越界异常 |
| 修改 next 后才保存后继 | 可能失去未处理部分入口 |
| 把尾指针当成尾节点的前驱 | 单链表无法直接向前走 |
| 用节点值判断有没有环 | 重复值合法，判断环需比较节点身份 |
| 暴露可修改的 Node | 外部可绕过 size 或制造环，破坏结构 |
| 反转后忘记修改表头入口 | 原头已经是尾，遍历可能只剩一个节点 |

## 11. 面试复述、练习与关联内容

> 单链表通过 next 引用连接节点，下标访问必须从表头逐步定位。已知前驱后插入、删除只修改常数个连接，但按下标操作仍可能 O(n)。我使用哨兵统一头部与中间操作。反转时先保存当前节点原后继，再把 next 指向已反转部分，最后移动两个遍历引用，时间 O(n)、辅助空间 O(1)。
