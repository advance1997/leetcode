# 链地址哈希表（ChainingHashMap）

[总览](HashTable.md) · [Java 实现](../../src/learning/datastructures/hashtable/ChainingHashMap.java)

## 1. 桶数组加冲突链

容量从 4 开始，每个桶存一条单链表的头。每个节点包含 key、value、next；键不可修改，值可覆盖。

```text
桶 0 → null
桶 1 → [5:50] → [1:10] → null
桶 2 → null
桶 3 → null
```

图中 key:value 表示键值映射。每个不同键恰好出现一次，节点所属桶必须等于 `bucketIndex(key, capacity)`，size 等于所有桶节点数。快照顺序按实现扫描，但 API 不承诺任何排序。

## 2. put：先查重，再扩容，再头插

put(1,10) 建立第一项；put(5,50) 在容量 4 时冲突，头插到同一桶，得到上图。put(1,11) 扫描桶 1，找到完整键 1 后只改 value，不创建新节点、不增加 size，也不因阈值触发扩容。

新键插入前，如果 size 已达到 `C-C/4`，则容量翻倍；容量上限 1<<30，无法继续满足负载限制时拒绝新键，已有键仍可更新。然后按当前容量计算桶，令新节点.next=旧桶头，再更新桶头。

为什么不能只判断“桶非空就覆盖”？因为同桶的 1 和 5 是不同键，覆盖会丢失映射。为什么扩容后还要重新计算本次下标？因为容量掩码已经改变。

## 3. get 与 containsKey

只扫描目标桶，从链头逐项比较 key，找到则返回值；到 null 表示缺失。get 缺失抛 NoSuchElementException，containsKey 返回 false。允许负数和所有 int 边界，因此不能用 -1 值代表缺失。

若无哈希分桶，朴素链表字典每次扫描全表 O(n)；分桶的优势是分布好时只扫描短链。代价是桶数组额外空间以及分布不佳时仍可能退化。

## 4. 删除桶头、中间和桶尾

容量 8 时键 1、9、17 都映射到桶 1，依次插入后：

```text
桶 1 → [17] → [9] → [1] → null
```

| 目标 | 修改 | 结果 |
| --- | --- | --- |
| 17（头） | buckets[1]=17.next | `9→1` |
| 9（中） | 17.next=9.next | `17→1` |
| 1（尾） | 9.next=null | `17→9` |

表中三行各从原始状态独立操作。删除保存前驱，命中后绕过节点并 size--，返回旧值；缺失不修改。只有一个节点时头分支将桶设为 null。移除引用不保证 JVM 立即回收内存。

## 5. 扩容必须重新分桶

容量 4 时 1 与 5 都在桶 1；容量变 8 后：

```text
旧：桶 1 → 5 → 1
新：桶 1 → 1
    桶 5 → 5
```

源码逐桶遍历，先保存 current.next，再用新容量计算下标并头插到新桶。若先改 next 再寻找旧后继，会沿新链走错，遗漏原节点。迁移不调用公开 put，不做重复查重，也不修改 size。

正确性：每个旧节点被访问一次，保存旧后继确保不会跳漏；重新计算下标确保每个键符合新桶规则，头插只改变同桶顺序，不改变键值。所有节点仍唯一且计数不变。

## 6. 正确性与成本

查找只访问键必属的桶，逐项比较完整键不会误认冲突。新键查重后插入保证唯一性，覆盖保持计数，删除只改变目标所在链的连接。扩容保持同一映射集合，因此 get/containsKey/remove 的语义不变。

n 为项数、C 为桶数：查询、删除期望 O(1) 依赖良好分布和受控负载，最坏链长 n，时间 O(n)。新增的普通头插 O(1)，但查重仍有上述成本；扩容扫描 C 桶并迁移 n 节点，O(C+n)，额外桶数组 O(C)。几何增长下插入期望均摊 O(1)。

存储 O(C+n)，不缩容；快照扫描全部桶，O(C+n) 时间、O(n) 返回空间。这里不把冲突链转换成树，不具备 Java HashMap 的相关优化。

## 7. 运行与完整结果

在仓库根目录执行，普通 JDK 可用 javac：

```bash
build_dir=$(mktemp -d /tmp/chaining-map.XXXXXX)
java -m jdk.compiler/com.sun.tools.javac.Main -encoding UTF-8 \
    -d "$build_dir" src/learning/datastructures/hashtable/ChainingHashMap.java
java -cp "$build_dir" learning.datastructures.hashtable.ChainingHashMap
```

main 执行 put(1,10)、put(5,50)、put(1,11)，读取数量和键 1；删除 1 后仍能读取 5；再加入最小整数键，值为 -1：

```text
2
11
11
50
false
-1
```

示例只展示接口，长冲突链和多次扩容另行验证。

## 8. 易错点与练习

常见错误：同桶直接覆盖；重复键 size++；删头未更新桶入口；改 next 后丢失旧后继；扩容不重新计算桶；假设 entries 有顺序；把负整数映射成负下标。

建议手画容量 4 的第四个不同键插入触发扩容，再删除一个碰撞键，核对所有剩余键。需要独立预期值，不能只让两个可能同样有错的实现互相比。
