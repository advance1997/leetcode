# 数组栈（ArrayStack）

[栈总览](Stack.md) · [Java 实现](../../src/learning/datastructures/stack/ArrayStack.java) · [数组基础](../array/Array.md)

## 1. 状态定义与边界

有效元素存放在 `[0,size)`，栈底是下标 0，栈顶是 size-1，下一次写入位置是 size。数组 length 是容量 C，必须满足 `0 <= size <= C`。

```text
下标：      0    1    2    3
数组：     [10,  20,  30,   0]
            底        顶   空闲槽位
size=3，capacity=4；快照顺序为 [30,20,10]
```

0 也可以是数据，判空看 size。默认容量为 4，可通过构造参数指定非负初始容量，容量为 0 也合法。构造容量不代表创建了对应数量的有效元素；负容量抛 IllegalArgumentException。

## 2. push、pop、peek 的顺序

push 先保证有空槽位，再写 elements[size]，最后 size++。容量足够时没有搬移。

```text
初始： [10,20, 0, 0] size=2
push(30)：写下标 2 → [10,20,30,0] → size=3
peek()：读 size-1，即下标 2，返回 30，size 仍为 3
pop()：先验证非空 → size=2 → 读下标 2 → 清零该槽位 → 返回 30
```

清零是整数教学实现便于观察的约定；泛型引用数组应清除废弃引用，避免继续保留已弹出的对象。判断数据是否有效始终依赖 size。

正确性：初始有效区间为空。push 在第一个无效槽位追加新值，使它成为末端且不改变旧元素次序；pop 只删除末端，所以恰好返回最近加入且尚未移除的元素。peek 不修改区间。异常检查先执行，保持空栈不变量。

## 3. 扩容：为什么通常翻倍

容量为 2，已有 `[10,20]`，继续 push(30)：

```text
旧数组： [10,20]            size=2，容量=2
新数组： [10,20,0,0]        先复制旧内容到容量 4 的数组
写入后： [10,20,30,0]       size=3
```

若每次只多分配一个槽位，连续入栈 m 次会复制 `1+2+...+(m-1)` 个元素，累计 O(m²)。按倍数增长时，复制量形成几何级数，例如容量从 1 开始入栈 9 个元素，复制 `1+2+4+8=15` 个元素，最终容量 16。

一般连续入栈 m 次，总复制量为 O(m)，加上 m 次写入仍为 O(m)，因此每次**均摊 O(1)**。均摊是对操作序列分摊，不是随机输入下的平均，也不保证触发扩容的那一次很快。

零容量先扩到 1，防止 `0*2` 永远为 0。源码先用 long 计算两倍容量，再将上限限制为 Integer.MAX_VALUE，避免 int 乘法溢出。到达计数上限时 push 显式拒绝；实际 JVM 可能因数组长度或内存限制更早抛出 OutOfMemoryError，整数上限不是分配成功保证。

## 4. 为什么暂不缩容

pop 保留旧数组以供复用，避免容量临界点附近反复 push/pop 导致频繁申请复制。代价是峰值之后的闲置空间；当前只剩 1 个元素，底层仍可能很大。

若增加自动缩容，不能在刚低于容量时立即收缩，否则可能抖动。可考虑占用率降到四分之一再缩到一半，并分析最小容量、均摊成本；这是扩展讨论，本实现没有自动缩容。

固定容量栈也常见：初始化最大容量，满时拒绝 push，避免运行中扩容；它适合上限明确的场景，但需要定义满栈异常或失败返回值。本节实现动态容量版本，不将固定容量策略描述为已提供的独立类。

## 5. 复杂度与实现取舍

n 为有效元素数，C 为保留容量。构造分配容量 C 的数组需要相应初始化空间和时间；不能将任意大容量构造称为 O(1)。

- 容量充足的 push、pop、peek、size、isEmpty：O(1)。
- 满容量 push：复制 n 个元素并初始化新数组，时间 O(n)，扩容时额外数组 O(n)；连续 push 均摊 O(1)。
- toArray：O(n) 时间，返回新数组 O(n) 空间，不改变栈；顺序为顶到底。
- 保留存储：O(C)，pop 不缩容；默认小容量开始时 C 与历史峰值规模相关。

相比把下标 0 作为栈顶并反复搬移，末端操作消除了每次 O(n) 的移动；相比链式栈，省去逐节点对象分配，但需要容忍偶发复制和空闲容量。
