## 2. 为什么“最后加入”先出来

可以把栈想成只允许从顶端放入和拿取的盘子。先 push(10)，再 push(20)、push(30)：

```text
栈顶 → [30]    下一个 pop 返回 30
       [20]
栈底 → [10]
```

连续弹出顺序为 30、20、10，称为 LIFO（Last In, First Out）。栈的作用不是排序，大小关系无关；重复值与负数都能正常保存。

| 操作 | 含义 | 是否修改内容 |
| --- | --- | --- |
| push(value) | 放到栈顶 | 是 |
| pop() | 移除并返回栈顶 | 是 |
| peek() | 仅查看栈顶 | 否 |
| size() | 当前有效元素数 | 否 |
| isEmpty() | 是否没有元素 | 否 |
| toArray() | 教学用快照，统一从栈顶到栈底 | 否，返回独立数组 |

不提供任意下标插删，是为了保持栈的访问语义。快照用于观察和验证，不应在每次 push/pop 后调用并把整个过程仍称为 O(1)。

## 3. 一组完整的操作追踪

| 操作 | 返回值 | 操作后栈（顶→底） |
| --- | --- | --- |
| push(10) | — | `[10]` |
| push(20) | — | `[20,10]` |
| push(30) | — | `[30,20,10]` |
| peek() | 30 | `[30,20,10]` |
| size() | 3 | `[30,20,10]` |
| pop() | 30 | `[20,10]` |
| push(40) | — | `[40,20,10]` |
| pop() | 40 | `[20,10]` |
| pop() | 20 | `[10]` |
| pop() | 10 | `[]` |

空栈的 peek/pop 统一抛出 `NoSuchElementException`，不返回 -1 或 0，因为这两个数也可能是合法数据。检查发生在修改之前，失败不能使 size 变为负数。两个实现均允许任意 int 值，不支持并发使用。

## 4. 为什么选择数组末端或链表头部

朴素数组实现若把下标 0 当栈顶，每次入栈都右移已有元素，每次出栈都左移，单次 O(n)。把栈顶放在有效区间末端，就只需更新一个槽位和 size，消除了重复搬移。

单链表若把尾节点当栈顶，出栈要找前驱，通常 O(n)。把头节点当栈顶，push 为头插，pop 为头删，两者都只修改固定数量引用。

优化思维是：根据数据结构擅长的操作选择逻辑端点，而不是先固定端点再承受不必要的遍历。

## 5. 实现比较

令 n 为当前元素数量，C 为数组保留容量；复杂度按通常基本操作及节点分配模型分析，不是 JVM 实时延迟保证。

| 项目 | 数组栈 | 链式栈 |
| --- | --- | --- |
| push | 均摊 O(1)，扩容时 O(n) | O(1)，每次新建节点 |
| pop、peek、size、判空 | O(1) | O(1) |
| 快照 | O(n) 时间及返回空间 | O(n) 时间及返回空间 |
| 存储空间 | O(C)，弹出不缩容 | O(n) 个可达节点 |
| 特点 | 紧凑，减少每元素对象分配 | 不需整体扩容复制 |
| 代价 | 闲置容量、偶发复制 | 每节点对象与引用开销 |

数组栈不缩容，因此大量弹出后，容量可能远大于当前 n，不能声称总是只占 O(n) 当前元素空间。链式栈弹出后节点不再由栈保留，实际内存回收时间仍由垃圾收集器决定。

## 6. Java 中通常怎么用栈

业务代码常用 `Deque<E>` 的栈方法，并用 `ArrayDeque<E>` 实现，而不是优先选旧的 `java.util.Stack`。示意：

```java
java.util.Deque<Integer> stack = new java.util.ArrayDeque<>();
stack.push(10);
stack.push(20);
int top = stack.peek();  // 20，不移除
int popped = stack.pop(); // 20，移除
```

这是可放入方法体的 API 用法片段。ArrayDeque 不允许 null；Deque.peek 在空时返回 null，pop 在空时抛 NoSuchElementException。上例把 peek 返回的 Integer 自动拆箱成 int，所以使用时需要保证非空，否则可能抛 NullPointerException。本仓库的教学 int 栈采用空时 peek 也抛异常的约定，两者不要混淆。

Deque.push/pop/peek 都在队首端配合使用；不要把 addLast 与 pop 随意混用后仍认为是同一端的栈。LinkedList 也实现 Deque，但多了链表节点开销；选择应考虑实际需求。Stack 的同步方法也不意味着“先判空再弹出”这样的多步操作天然原子。

## 7. 应用、常见错误与迁移

栈适合处理“最近尚未完成的任务”：括号匹配先关闭最近打开的括号，显式深度优先搜索先探索最近加入的待访问节点，撤销操作先撤销最近动作。函数调用也具有嵌套返回次序，但 JVM 调用栈不等同于这里的堆上容器对象。

关联练习包括 20「有效的括号」、155「最小栈」、150「逆波兰表达式求值」、739「每日温度」。本次仅完成基础数据结构，不新增这些算法题解。仓库已有[历史括号代码](../../src/simple/ValidBrackets.java)，可对照阅读，不代表已按当前规范重写。

常见错误：把 peek 当 pop；数组 push 先增加 size 后写错位置；空栈时直接 --size；把有效值 0 当空标记；把每次数组 push 都说成最坏 O(1)；为链式栈选用单链表尾删；快照顺序在两种实现之间不一致。

## 8. 面试复述与练习

> 栈只在栈顶操作，因此后进先出。数组实现把栈顶放在有效区间末尾，容量不够时扩容，入栈均摊 O(1)、单次扩容 O(n)。链式实现把栈顶放在单链表头部，头插头删都是 O(1)，代价是每次分配节点。空栈操作的行为要先定义，peek 不改变状态。

建议手写一组交错 push/pop，画出 size 或 top；解释为什么单链表尾端不适合栈顶；计算容量为 1 的数组连续入栈 9 次时的复制次数。练习为建议，不代表学习者已经完成。
