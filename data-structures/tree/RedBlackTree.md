# 红黑树：用颜色约束控制搜索树高度

[返回树专题](Tree.md) · [Java 实现](../../src/learning/datastructures/tree/RedBlackTree.java) · [上一节：AVL](AvlTree.md)

## 1. 本节学习目标与实现范围

普通 BST 的顺序性质让我们能够排除一半方向，却不保证排除一半节点；按顺序插入时仍可能退化为链表。上一节 AVL 用每个节点的高度差限制退化，本节改用颜色和路径黑节点数约束高度。

本节实现经典红黑树整数集合，包括插入、删除、查找、最值、中序快照；采用父指针与共享黑色 NIL 哨兵。它不是左倾红黑树（LLRB），不要求红链接只朝左，也没有实现泛型映射、并发集合或区间统计。基础数据结构不对应某一道 LeetCode 题目，不虚构题号和难度。

## 2. 从直接办法到平衡搜索树

| 方案 | 查找 | 插入、删除 | 优点与代价 |
| --- | --- | --- | --- |
| 无序数组逐项扫描 | O(n) | 查重或找删除位置 O(n) | 直观，连续存储，但每次查找重做大量比较 |
| 有序数组二分 | O(log n) | 搬移元素最坏 O(n) | 查询快，更新昂贵 |
| 普通 BST | O(h)，最坏 O(n) | O(h)，最坏 O(n) | 有序结构，但高度依赖插入顺序 |
| AVL | 最坏 O(log n) | 最坏 O(log n) | 高度约束更紧，需要维护高度及再平衡 |
| 红黑树 | 最坏 O(log n) | 最坏 O(log n) | 颜色约束允许更宽松的平衡，更新修复情况较多 |

这里 n 为非空集合的元素数，h 为树高。空集合操作为 O(1)。不要把红黑树描述成“每次把树完全平分”：它只控制最长路径与最短路径的关系，从而保证对数高度。与 AVL 相比，实际速度还取决于数据分布、对象布局和实现，不能直接断言谁总是更快。

## 3. 存储方式、NIL 与五条性质

节点保存 `value`、`red`、`left`、`right`、`parent`。`red=true` 表示红色，false 表示黑色。图中 B 为黑，R 为红，省略的孩子均为黑色 NIL。

红黑树首先是一棵严格 BST：左子树所有值小于节点，右子树所有值大于节点；重复插入返回 false。在此基础上满足：

1. 每个节点是红色或黑色。
2. 根为黑色。
3. 所有 NIL 叶子为黑色。
4. 红节点的孩子都是黑色，不能出现相邻的红节点。
5. 从任意节点到其下方 NIL 的所有路径具有相同的黑节点数。

```text
             20B
            /   \
          10R   30R
         /  \   /  \
        NIL NIL NIL NIL
```

“叶子为黑”说的是 NIL，不是值为 10、30 的业务叶子。上图的业务叶子可以为红。

代码只创建一个共享 NIL 对象，所有缺失孩子引用它。它的值 0 没有业务含义；真正的整数 0 用另一个节点保存，通过对象身份区分。空树 `root == nil`，NIL 不计入 size。

常态下 NIL 的 left、right、parent 都指向自身。删除时，`nil.parent` 可以临时记录正在修复的缺失位置的父节点，删除完成后恢复自身。它不能同时代表所有缺失位置的父节点，不能沿 NIL 的父指针做一般遍历。

## 4. 为什么这些规则保证对数高度

为避免黑高定义歧义，本节推导使用 b(x)：从 x 向下到 NIL 的路径上，**不计 x、计入末端 NIL** 的黑节点数，并定义 b(NIL)=0。

可以归纳证明：以 x 为根的子树至少有 `2^b(x)-1` 个业务节点。NIL 是基例；每个孩子的黑高至少是 `b(x)-1`，所以两个孩子的最少节点数加上 x，至少为 `2 × (2^(b(x)-1)-1)+1`。

设 h 是从根到 NIL 最长路径的边数，也等于最长路径的业务节点层数。由于不能红红相邻，这条路径在不计根、计 NIL 的 h 个节点中至少一半为黑，因此 `b(root) >= h/2`。于是：

```text
n >= 2^b(root) - 1 >= 2^(h/2) - 1
h <= 2 log2(n+1)
```

关键思维是：不直接要求左右高度接近，而是先让黑色层数一致，再限制两个黑色层之间最多插入一个红色节点。

## 5. 旋转为什么不破坏搜索顺序

```text
       p                         s
      / \       左旋 p          / \
     A   s       ----->        p   C
        / \                   / \
       B   C                 A   B
```

旋转前后中序都是 `A、p、B、s、C`。变化的是局部连接及子树入口，不是值的顺序。右旋完全对称。

代码必须同时更新：中间子树 B 的父节点、旧父节点指向新根的连接、整树 root（若旋转发生在根）、p 与 s 的父子连接。`rotateLeft/rotateRight` 本身不变色，颜色由修复逻辑统一决定。

尤其不能在旋转中随意给共享 NIL 改 parent：B 为 NIL 时跳过这一步，才能保留删除过程中缺失位置的父信息。

## 6. 插入：为什么先染红，再处理红红冲突

按普通 BST 搜索找到缺失位置，新节点染红，两个孩子指向 NIL。原来的路径只是增加一个红节点，黑节点数没有增加，所以不会破坏黑高。可能破坏的是“根为黑”和“红节点无红孩子”。

父节点为黑时直接结束。父节点为红时，祖父一定存在且为黑，观察叔叔，也就是父节点的兄弟。下面先讲父节点在祖父左侧的情形，对应源码 I-L 分支。

| 情况 | 操作 | 为什么这样做 |
| --- | --- | --- |
| I-L1：叔叔红 | 父叔染黑、祖父染红，向祖父继续修复 | 两侧黑高同步保持，可能把红红冲突上移 |
| I-L2：叔叔黑，节点是父的右孩子 | 左旋父节点，把折线转直线 | 转换形态，不改中序和黑高 |
| I-L3：叔叔黑，节点是父的左孩子 | 父染黑、祖父染红，右旋祖父 | 新子树根为黑，消除红红冲突 |

I-L2 后紧接 I-L3。父节点在祖父右侧时交换左右，对应 I-R1/2/3。结束时将根染黑；根变黑会让整棵树所有路径同步加一个黑色，不影响一致性。

### 具体追踪：插入 10、20、30，再插入 15

```text
插入 10、20：       插入 30（修复前）：       I-R3 修复后：
   10B                  10B                    20B
      \                    \                  /   \
      20R                  20R              10R   30R
                              \
                              30R
```

30 的父为红，叔叔为黑色 NIL；这是右右直线，20 染黑、10 染红、左旋 10。

```text
再插入 15：             父叔变黑、祖父变红：       最后根染黑：
       20B                       20R                   20B
      /   \                     /   \                 /   \
    10R   30R                 10B   30B             10B   30B
      \                         \                     \
      15R                       15R                   15R
```

本次触发 I-L1，不需要旋转。单次插入最多两次旋转，但变色可以一路传播到根，因此总时间仍为 O(log(n+1))。

## 7. 删除：先确定哪个位置真正少了黑色

先复用 BST 删除框架：

- 目标没有左孩子：用右孩子接替目标。
- 目标没有右孩子：用左孩子接替目标。
- 目标有两个孩子：找到右子树最小节点，即中序后继，将后继移植到目标位置。

这里采用节点移植，值字段保持 final。双孩子删除时，后继在新位置继承目标颜色；是否需要修复，依据的是**后继离开旧位置之前的颜色**，而不是目标原来的颜色。

后继没有左孩子，所以替代旧位置的节点是后继的右孩子 `replacement`，可能为 NIL。后继恰好是目标右孩子时，replacement 的父直接设置为后继；后继位于更深处时，先将后继右孩子接回旧父，再把后继接到目标位置，不能丢失右子树。

删除红节点不会减少路径黑色数量。删除黑节点后：

- replacement 是红色：把它染黑即可补足。
- replacement 已是根：所有路径统一少一个黑色，可以结束。
- replacement 为非根黑节点或 NIL：它所在路径少一个黑色，需要下面的修复。

常说的“双黑”是分析用的额外黑色记账，代码没有第三种颜色；循环变量 node 标记当前需要补偿的位置。

### 四种兄弟情况

先令 x 为缺失位置，p 为父节点，s 为右侧兄弟，即 x 在左侧。近侄是 `s.left`，远侄是 `s.right`。x 在右侧时左右互换，不能仍把 right 固定当成远侄。

| 源码分支 | 条件 | 处理及后续 |
| --- | --- | --- |
| D-L1 | s 红 | s 黑、p 红，左旋 p；重新获取黑兄弟，进入后续情况 |
| D-L2 | s 黑，两个侄子黑 | s 染红，x 上移到 p；若 p 红则最终染黑吸收，否则继续向上 |
| D-L3 | s 黑，近侄红、远侄黑 | 近侄黑、s 红，右旋 s；重新取兄弟，转成 D-L4 |
| D-L4 | s 黑，远侄红 | s 继承 p 颜色，p 与远侄染黑，左旋 p，修复结束 |

镜像分支为 D-R1 至 D-R4。D1、D3 是转换步骤，不应执行完就直接退出；D2 可能传播，D4 才在局部完成补偿。

D2 为什么上移？兄弟染红后，兄弟侧也少一个黑色，两侧重新相等，但整个 p 子树相对外部少一个黑色，于是将欠缺交给 p。有效的删除修复循环中，s 不会是 NIL：欠缺发生前两侧黑高相同，另一侧必须有足够的黑色贡献。源码据此可以给 s 变色；若把树外部破坏，这个前提就不再成立。

D4 的颜色转移示意（c 是 p 原来的颜色，x 带一份概念上的欠缺）：

```text
       p(c)                         s(c)
      /    \                       /    \
     x     s(B)      ----->       p(B)   f(B)
          /   \                 /   \
         N    f(R)             x     N
```

x 侧新增一个黑色 p，补足欠缺；其他路径通过 s、p、f 的颜色转移保持原有黑色贡献。旋转仍保持 BST 顺序，因此可以停止。

### 具体删除追踪：插入 2、1、3、0 后删除 3

插入 0 时父叔变黑，得到下图。删除黑色业务叶子 3 后，x 是右侧 NIL，兄弟 1 为黑，远侄 0 为红，触发 D-R4。

```text
删除前：             删除 3，右侧缺黑：         修复后：
       2B                    2B                    1B
      /  \                  /  \                  /  \
     1B  3B                1B   x=NIL             0B  2B
    /                     /
   0R                    0R
```

1 继承 2 的黑色，2 保持黑色，0 染黑，右旋 2。修复前右侧从 2 到 NIL 少一个黑色，修复后每条根到 NIL 路径都包含三个黑节点（本句计根和 NIL），黑高重新一致。

经典删除最多三次旋转：D1 一次、D3 一次、D4 一次。只有 D2 会把问题向上传递，传播时不旋转；D1 后父为红，若进入 D2 可直接吸收，否则经 D3/D4 完成，不会再累积另一组旋转。总时间为 O(log(n+1))。

## 8. 正确性如何串起来

搜索始终按全局 BST 顺序排除不可能包含目标的子树。插入仅接入一个新值，删除通过中序后继保持两侧值域；旋转不改变中序序列，所以集合内容与顺序始终正确。

插入时黑高原本未变，只修复红红冲突；每次变色将冲突上移，或旋转局部消除，最后根染黑。删除时只需补偿一个位置的黑色欠缺；四种情况保持其他位置的性质，转换、上移或消除欠缺。向上移动次数受树高限制，转换后能进入终止或上移步骤，所以修复能够终止。

公开操作完成后，根黑、NIL 黑、无红红、黑高一致，加上 BST 顺序，就得到合法红黑树。仅检查中序输出无法证明这些性质。

## 9. 接口、复杂度与运行

| 接口 | 行为 | 最坏时间 | 辅助空间（不含存储和返回值） |
| --- | --- | --- | --- |
| add(value) | 新增 true，重复 false | O(log(n+1)) | O(1) |
| remove(value) | 删除 true，缺失 false | O(log(n+1)) | O(1) |
| contains(value) | 是否存在 | O(log(n+1)) | O(1) |
| min() / max() | 空树抛 NoSuchElementException | O(log(n+1)) | O(1) |
| size() / isEmpty() | 读取状态 | O(1) | O(1) |
| inorder() | 返回独立的升序 int 数组 | O(n) | O(log(n+1)) 显式栈 |

空树均按 O(1) 处理。inorder 另需 O(n) 返回空间；全部节点占 O(n) 存储。增删修复使用父指针迭代，无递归栈。支持 int 最小值、最大值和 0；直接比较大小，不通过相减比较，避免溢出。新值插入超过计数上限时抛 IllegalStateException，实际容量先受到内存限制。

## 10. 常见错误、用途与面试复述

- 把 NIL 当作值为 0 的业务节点，或者把业务叶子强制染黑。
- 双孩子删除只检查 target 的颜色，遗漏后继旧位置少黑的问题。
- 后继移植时丢掉它的右孩子；旋转后忘记更新 root 或父指针。
- D1/D3 旋转后继续使用旧 sibling，导致判断错位。
- 镜像分支只替换旋转方向，却没有交换近侄和远侄。
- 遍历共享 NIL 不设置停止条件，沿自引用陷入死循环。
- 对外暴露节点供随意修改，破坏排序与颜色不变量；本实现不暴露节点，也不支持并发修改。

红黑树适合需要有序更新、最值和范围扩展的集合或映射。若只需要无序键查找，可比较哈希表；若查询占绝大多数且更新很少，也应考虑有序数组的连续存储优势。本类尚未提供范围查询接口。

可复述为：“先保证 BST 顺序，再用相同黑高和禁止红红把高度限制为对数。插入红节点避免先破坏黑高，按叔叔颜色处理；删除记录真正移走节点的原始颜色，围绕欠缺位置按兄弟及侄子颜色修复。旋转维护顺序，变色维护路径的黑色贡献。”

可关联 LeetCode 98（验证二叉搜索树）、450（删除二叉搜索树中的节点）、110（平衡二叉树），用于巩固顺序、删除和高度概念；这些题并不都要求实现红黑树。下一步学习多叉树的孩子列表表示与遍历。
