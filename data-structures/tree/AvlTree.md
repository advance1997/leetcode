# AVL 平衡树：用局部旋转控制高度

[树专题](Tree.md) · [普通二叉搜索树](BinarySearchTree.md) · [Java 实现](../../src/learning/datastructures/tree/AvlTree.java)

学习日期：2026-11-11（北京时间）。本节在 BST 的有序约束上增加高度约束，实现插入与删除的自动再平衡。它仍是整数集合，不是另一种允许重复值或键值映射的接口。

## 1. 从退化问题想到平衡

普通 BST 依次插入 10、20、30，会得到向右延伸的链。继续升序插入 n 个元素，树高可能为 n，查询 O(n)，整个构造 O(n²)。

朴素修复方法是每次更新后收集中序结果，再用中点递归重建平衡树，单次至少 O(n)，而且要扫描未受影响部分。AVL 观察到：新增或删除一个节点，只有它到根的祖先路径可能改变高度，因此只在该路径维护高度，并用局部旋转恢复平衡。

## 2. 高度、平衡因子与不变量

空子树高度为 0，叶节点高度为 1，高度按层数。每个节点保存：

```text
height(node) = 1 + max(height(left), height(right))
balance(node) = height(left) - height(right)
```

AVL 要求每个节点的平衡因子只能为 -1、0、1，且左子树全部键小于根、右子树全部键大于根。仅检查根是否平衡不够；缓存的 height 也必须等于真实高度。

插删回溯中每个孩子已经处理完，先更新当前高度，再判断是否失衡。不要每次递归扫描整棵子树计算高度，否则会破坏 O(log n) 的更新成本。

## 3. 接口与实现选择

| 方法 | 行为 |
| --- | --- |
| add(value) | 新值返回 true，重复返回 false，size 不变 |
| remove(value) | 删除成功 true，缺失 false |
| contains(value) | 判断存在性 |
| min()/max() | 最值，空树抛 NoSuchElementException |
| size()/isEmpty() | 数量与判空 |
| height() | O(1) 读取根的缓存层数，空树为 0 |
| inorder() | 返回严格递增的独立 int 数组 |

支持全部 int 值，比较不用减法以免溢出。不暴露节点，不支持并发修改。新增超过 int 计数上限时抛 IllegalStateException，实际规模还受内存约束。

为把“是否改变集合”和“如何维护子树”分开，公开 add/remove 先 contains，再调用递归助手，因此走两次查找路径，但仍为 O(log(n+1))。重复插入、缺失删除不修改结构。size 仅在公开方法中修改一次，后继替换不会重复扣减。

与上一节不同，本节增删使用递归表达自底向上回溯。只要 AVL 不变量持续成立，递归深度为 O(log n)，不随升序输入退化到 n；不能把这个理由移植到未平衡 BST。

## 4. 右旋与左旋为什么保持顺序

右旋，以 y 为旧根、x 为左孩子，A、B、C 表示整棵子树（可为空）：

```text
        y                       x
       / \                     / \
      x   C     右旋          A   y
     / \                         / \
    A   B                       B   C
```

顺序始终为 `A < x < B < y < C`。B 原来是 x 的右子树，旋转后变为 y 的左子树，这两处都符合值范围。必须保留 B，不能直接丢弃。

关键连接是 `x.right=y`、`y.left=B`。旧根 y 下降，先更新 y.height，再用它的新高度更新 x.height，最后返回 x。调用方必须接住返回根，否则旋转后的子树可能从父节点入口丢失。

左旋完全对称：

```text
      x                           y
     / \                         / \
    A   y        左旋           x   C
       / \                     / \
      B   C                   A   B
```

旋转不创建或删除业务节点，保持中序序列；它改变结构和高度，不改变集合内容。

## 5. LL、RR、LR、RL 四种情况

名称描述失衡节点的较高侧及其孩子的较高方向，不是旋转方向。统一按高度因子判定：

| 当前因子 | 较高孩子因子 | 类型/处理 |
| --- | --- | --- |
| >1 | 左孩子 >=0 | LL 型，直接右旋；含删除时为 0 的情况 |
| >1 | 左孩子 <0 | LR，先左旋左孩子，再右旋当前根 |
| <-1 | 右孩子 <=0 | RR 型，直接左旋；含删除时为 0 的情况 |
| <-1 | 右孩子 >0 | RL，先右旋右孩子，再左旋当前根 |

四组最小插入实例，最终都得到根 20、左 10、右 30：

```text
LL：30,20,10          RR：10,20,30
      30                   10
     /                       \
    20                        20
   /                            \
  10                             30
→ 右旋 30               → 左旋 10

LR：30,10,20          RL：10,30,20
      30                   10
     /                       \
    10                        30
      \                      /
       20                   20
→ 左旋 10，再右旋 30     → 右旋 30，再左旋 10
```

双旋先把“折线”变成可单旋的形态。只根据被插入值判断方向的写法不适合通用删除再平衡；本实现统一看孩子的高度因子。

## 6. 插入后的完整回溯

依次插入 30、20、10：

| 时刻 | 当前节点 | 左高/右高 | 高度/因子 | 行为 |
| --- | --- | --- | --- | --- |
| 新建 10 | 10 | 0/0 | 1/0 | 返回叶节点 |
| 回到 20 | 20 | 1/0 | 2/+1 | 不旋转 |
| 回到 30 | 30 | 2/0 | 3/+2 | 左孩子因子 +1，右旋 |
| 旋转后旧根 30 | 30 | 0/0 | 1/0 | 先更新高度 |
| 旋转后新根 20 | 20 | 1/1 | 2/0 | 返回新根 |

公开方法执行 `root = insert(root,value)`。内部也必须写 `node.left = insert(...)` 或 `node.right = insert(...)`，才能接回可能变化的子树入口。

普通 BST 插入规则保证有序；回溯只改变更新路径上的节点，未受影响的子树不需要扫描。旋转保持中序不变，并恢复当前局部高度差，继续返回即可。

## 7. 删除：先按 BST 摘除，再一路修复

删除叶节点返回 null；只有一个孩子时返回该孩子；两个孩子时复制右子树最小节点的值，再从右子树递归删除后继。后继可能有右孩子，单孩子分支会保留它。回溯每层调用 rebalance，不能只调整一次就停止。

### 孩子平衡因子为 0 的情况

依次插入 `[4,2,5,1,3]` 后删除 5：

```text
删除前：        4           删除 5 后：      4
              / \                         /
             2   5                       2
            / \                         / \
           1   3                       1   3

根因子 +2，左孩子因子 0 → 直接右旋
结果：        2
             / \
            1   4
               /
              3
```

旋转后局部高度仍为 3。删除不一定让每个祖先高度降低，所以不能把“较高孩子因子为 0”错误归入双旋；右重侧同理。即使某层高度不再变化，本实现继续返回更新祖先，逻辑简单且仍为 O(log n)。

### 为什么可能连续调整多个祖先

某个子树删除后变矮，局部旋转可能使该子树高度比原来减少 1。它的父节点就可能从高度差 1 变成 2，因此还需在更高处旋转。插入的首次局部修复通常可恢复插入前高度，删除则可能继续向上传播。本实现不设置“旋转过就结束”的标志，沿删除路径全部回溯。

每个返回层都满足：孩子子树已正确、当前值满足 BST 顺序；先更新当前高度，必要时旋转，使该子树也恢复 AVL。不变量由下向上成立，最终到达根。公开 size-- 只执行一次。

## 8. 为什么高度是 O(log n)

设 N(h) 是高度为 h 的 AVL 所需最少节点数。最稀疏的合法情况中，两棵子树高度分别为 h-1、h-2：

```text
N(0)=0
N(1)=1
N(h)=1+N(h-1)+N(h-2)
```

这个增长与斐波那契数列同阶，随 h 指数增长，因此反过来 h=O(log(n+1))。保证来自每个节点的平衡约束，而非随机插入或树看起来对称。

## 9. 复杂度与取舍

| 操作 | 时间 | 辅助空间，不含返回值 |
| --- | --- | --- |
| contains、min、max | O(log(n+1))，空树 O(1) | O(1) |
| add、remove | O(log(n+1))，空树 O(1) | O(log(n+1)) 递归路径 |
| size、isEmpty、height | O(1) | O(1) |
| inorder | O(n) | O(log(n+1)) 显式栈，另返回 O(n) 数组 |

每次旋转 O(1)，每层最多常数次旋转与高度更新，路径长度对数级。节点总存储 O(n)，每个节点比普通 BST 多一个高度字段。两次查找路径只增加常数成本，不改变阶数。

相比每次收集并重建整树的 O(n) 调整，AVL 局部更新避免无关子树扫描；相比未平衡 BST，消除了升降序输入的线性高度，但增删代码和验证成本更高。红黑树采用不同平衡约束，更新规则与旋转次数取舍不同，不能把本实现称为红黑树或宣称 AVL 在所有工作负载上更快。

Java TreeSet/TreeMap 并不是本教学 AVL 类；这里保留已有集合接口是为了对照验证语义，不是复制其内部算法。

## 11. 易错点、复述与练习

常见错误：只检查根；旋转丢掉中间子树；先更新新根导致读取旧高度；没有接住旋转返回根；删除后只旋转一次；孩子因子 0 时误用双旋；后继删除重复减 size；每次用全树遍历计算高度。

> AVL 在 BST 顺序规则上要求每个节点左右高度差不超过 1。我缓存高度，插删按普通搜索树方式定位，在回溯时先更新高度，再依据当前和孩子的平衡因子选择单旋或双旋。旋转保持中序顺序；删除可能使高度继续减少，因此要修复整条祖先路径。最少节点数递推说明树高为对数级。

练习：手画四种最小插入旋转；验证右旋的 B 子树为何可接到旧根左侧；手算删除 5 的因子 0 例子；解释同样有序的中序数组为什么不足以证明平衡。相关 110「平衡二叉树」只判断平衡，并不等于实现动态 AVL。本次没有新增该题题解。
