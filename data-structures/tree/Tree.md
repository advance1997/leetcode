## 2. 树的基本定义

从图论看，树是连通且无环的无向图。选择一个根并将关系从根向下组织后，得到有根树。非空树中除根以外，每个节点恰有一个父节点；任意两个节点之间存在唯一简单路径。含 n 个节点的非空树有 n-1 条边。

```text
            A              根
          /   \
         B     C           A 的孩子；B 与 C 为兄弟
        / \     \
       D   E     F         叶节点
```

| 术语 | 含义与本例 |
| --- | --- |
| 根 | 没有父节点的 A |
| 父/子节点 | B 是 D 的父节点，D 是 B 的孩子 |
| 叶节点 | 无孩子的 D、E、F |
| 子树 | B 连同其后代 D、E 形成一棵树 |
| 祖先/后代 | A、B 是 D 的祖先 |
| 节点度数（有根树语境） | 孩子数量，B 为 2；不要与无向图邻接边数混淆 |

本专题约定根深度为 0，深度按从根到节点的边数计算；树高 h 按层数计算，空树 h=0，单节点 h=1，上图 h=3。其他资料可能按边数定义高度，比较公式前先统一口径。最大层宽 w 是任一层的最大节点数，上图 w=3。

空树由“没有根”表示。多个根且互不连接的树的集合称为森林。节点值重复不影响树结构，值不是节点身份；回边会形成环，共享子节点会使某节点拥有多个父节点，它们不属于本节的普通树模型。

## 3. 一般树与二叉树

一般树的孩子数量不固定。二叉树每个节点至多有两个孩子，且**区分左、右位置**：只有左孩子与只有右孩子是不同形状。

```text
   1          1
  /            \
 2              2
```

二叉树没有自动的数值大小规则。只有满足“左子树所有键小于根、右子树所有键大于根”（重复键策略另行定义）的结构，才是二叉搜索树。普通二叉树的中序输出并不一定递增。

常见形状不要混淆：

- 完美二叉树：所有内部节点有两个孩子，所有叶子同层；h 层有 2^h-1 个节点。中文“满二叉树”常用于此含义，英文 full 有时仅指每个节点有 0 或 2 个孩子，要明确语境。
- 完全二叉树：除最后一层外均填满，最后一层从左到右连续排列；适合紧凑数组存储。
- 退化树：每个非叶节点只有一个孩子，高度可达 n，形似链表。
- 平衡树：控制高度的结构；具体约束因 AVL、红黑树等类型而异，并非“看起来左右差不多”。

## 4. 常见存储方式

| 表示方式 | 方法 | 优势与限制 |
| --- | --- | --- |
| 二叉链式节点 | value、left、right | 稀疏树自然，无需大量空槽位；有对象与引用开销 |
| 完全位置数组 | 左孩子 2i+1、右孩子 2i+2 | 完全二叉树紧凑；退化树可能浪费大量位置，需分析下标溢出 |
| 一般树孩子列表 | 每个节点维护 children 列表 | 自然表达任意数量孩子；列表本身也有开销 |
| 双亲数组 | 每个位置记录父节点下标 | 找父节点方便，找全部孩子需要额外索引或扫描 |
| 左孩子右兄弟 | firstChild、nextSibling | 用两条引用表达多叉树；右引用表示兄弟，不是原树右孩子 |

本次 Java 采用二叉链式节点。输入数组只是构造格式，不是底层的完全位置数组；两者的下标语义在[二叉树讲解](BinaryTree.md)中具体演示。

## 5. 遍历为何有不同顺序

遍历需要决定“何时处理当前节点”。深度优先遍历围绕每个根有三种常见顺序：前序是根左右，中序是左根右，后序是左右根。层序使用队列，先处理浅层再处理深层，同层从左到右。

递归用调用栈保存“返回后还要做什么”，迭代用显式栈保存待处理节点或路径。队列先进先出保证已发现的同层节点先于下一层节点被处理。这将前面学过的栈和队列用到了非线性结构上。

树结构本身保证没有环且无共享孩子，所以本例遍历不需要 visited 集合。将同样写法直接用到一般图上可能重复访问甚至无限循环，图遍历需要另行处理。

## 6. 复杂度与场景

访问全部 n 个节点，输出每个节点值需要 Ω(n) 时间，合理实现达到 O(n)。不能为了形式上的“优化”声称递归换迭代就降低渐进时间；两者主要在控制方式、调用栈风险、实现难度上有差异。

DFS 的控制空间与高度 h 有关，BFS 的队列与最大层宽 w 有关；平衡树 h 通常为 O(log n)，退化树为 O(n)。若返回全部遍历结果，还必须计入 O(n) 输出存储。递归在深树可能耗尽调用栈，显式栈也占内存，只是不使用逐层 Java 方法调用。

树适合目录、组织层级、语法结构；搜索树适合有序查找；堆适合优先级；前缀树适合共享字符串前缀。选择取决于规则和操作需求，不是所有树都能 O(log n) 查找。
