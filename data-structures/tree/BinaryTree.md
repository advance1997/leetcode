# 普通二叉树（BinaryTree）：构造与七种遍历实现

[树专题总览](Tree.md) · [Java 实现](../../src/learning/datastructures/tree/BinaryTree.java)

学习日期：2026-11-10（北京时间）。节点为整数 value、left、right，孩子为空时为 null。工厂构建后不提供修改接口，也不暴露节点；所有遍历返回独立 int 数组，重复调用不改变树。

## 1. 紧凑层序输入与接口

`fromLevelOrder(Integer[] values)` 按队列依次取出实际父节点，为其读取最多两个输入位置：先左后右。null 表示缺失孩子，缺失孩子不进入父节点队列。

```text
输入：[1, 2, 3, null, 4, 5]

        1
       / \
      2   3
       \ /
        4 5
```

| 构造阶段 | 当前父节点 | 消耗输入 | 队列（首→尾） |
| --- | --- | --- | --- |
| 根入队 | — | 1 | `[1]` |
| 处理 1 | 1 | 2、3 | `[2,3]` |
| 处理 2 | 2 | null、4 | `[3,4]` |
| 处理 3 | 3 | 5，右孩子省略 | `[4,5]` |
| 输入结束 | — | — | 尚未提供孩子的节点保持为叶子 |

队列里没有 null，适配 ArrayDeque 的非空元素要求。每个新节点只被一个父节点连接，因此不会形成共享子节点或环。

**不要套用完全位置下标公式：**`[1,null,2,3]` 表示根 1 只有右孩子 2，2 的左孩子是 3。这里下标 3 的值属于节点 2，而不是缺失的节点 1（数组下标）的孩子。`2i+1/2i+2` 只适用于另一种按完整位置占位的表示。

| 输入 | 行为 |
| --- | --- |
| `[]`、`[null]`、全 null 数组 | 空树 |
| `[1]` 或 `[1,null,null,null]` | 单节点树，允许尾部冗余 null |
| null 数组引用 | 抛 IllegalArgumentException |
| `[null,1]`、`[1,null,null,2]` | 有效值无法归属父节点，抛 IllegalArgumentException |
| 重复值、0、负数、int 两端边界 | 都是合法节点值 |

工厂不修改或保留输入数组引用。构造时拒绝孤立值，避免默默丢弃输入。没有一般意义的按值 insert/remove，因为普通树没有规定插入位置和删除后连接规则；这些会在搜索树专题定义。

## 2. 四种顺序的独立预期

对上面的五节点示例：

| 遍历 | 规则 | 结果 |
| --- | --- | --- |
| 前序 | 根、左子树、右子树 | `[1,2,4,3,5]` |
| 中序 | 左子树、根、右子树 | `[2,4,1,5,3]` |
| 后序 | 左子树、右子树、根 | `[4,2,5,3,1]` |
| 层序 | 层从浅到深，同层从左到右 | `[1,2,3,4,5]` |

“前/中/后”指根节点相对于左右子树的访问时机，不是左孩子和右孩子谁先遍历。这三种都先处理左子树再处理右子树。普通树中序无排序保证，本例明显不是递增序列。

API 分别为 preorderRecursive/Iterative、inorderRecursive/Iterative、postorderRecursive/Iterative，以及 levelOrder。空树均返回空数组。levelOrder 只返回真实节点值，没有 null 占位，**不是**能完整恢复形状的序列化输出。

## 3. 递归：只改变处理根的位置

每次函数负责一棵以 node 为根的子树，node=null 直接返回。前序先记录根再递归左右，中序先左再根再右，后序先左右再根。

```text
前序：记录 node → 递归 left → 递归 right
中序：递归 left → 记录 node → 递归 right
后序：递归 left → 递归 right → 记录 node
```

以中序为例：从 1 进入 2，2 的左为空，先输出 2；进入 4 输出 4；返回 1 输出 1；进入 3 的左孩子 5，输出 5 后再输出 3。结果不是简单把整棵树“从左到右看一遍”，而是递归执行每棵子树的同一规则。

正确性按子树归纳：空树输出空序列；假设左右子树输出正确，将根放到规定位置即可得到当前树的正确顺序。每个节点恰好作为一次非空调用的根，访问一次且不遗漏，有限树必然终止。

## 4. 迭代前序：右先入栈，左先出栈

初始把根入栈。每次弹出并输出，再先压右孩子、后压左孩子。

| 弹出/输出 | 压入操作 | 栈（顶→底） | 累计输出 |
| --- | --- | --- | --- |
| 初始 | 根 1 | `[1]` | `[]` |
| 1 | 3，再 2 | `[2,3]` | `[1]` |
| 2 | 右孩子 4 | `[4,3]` | `[1,2]` |
| 4 | 无 | `[3]` | `[1,2,4]` |
| 3 | 左孩子 5 | `[5]` | `[1,2,4,3]` |
| 5 | 无 | `[]` | `[1,2,4,3,5]` |

栈保存待访问子树的入口，栈顶总是接下来应访问的根。后进先出使左子树先完成，未访问的右子树入口留在栈中，故得到根左右顺序。

## 5. 迭代中序：保存尚未输出的祖先

循环中一路向左，将节点压栈。走到 null 后弹出一个祖先并输出，然后转向其右子树。

```text
压 1，压 2，左边到 null
弹 2 → 输出 2 → 转向 4
压 4，左边到 null → 弹 4 → 输出 4
弹 1 → 输出 1 → 转向 3
压 3，压 5 → 弹 5 → 输出 5
弹 3 → 输出 3，结束
```

关键不变量：栈中节点等待左侧处理完成后被输出。弹出时其左子树已完成，输出后才进入右侧，满足左根右。外层条件必须是 `current != null || !stack.isEmpty()`，否则当前指针为空但祖先仍待处理时会提前结束。

## 6. 迭代后序：根要等右子树完成

只用普通前序栈无法直接决定“什么时候输出根”。一种直观方案是得到根右左序列再反转或使用双栈，需要额外 O(n) 缓存；本实现采用单栈加 lastVisited，控制空间 O(h)。结果列表本身仍占 O(n)，不要把整体空间说成只有 O(h)。

先一路压左侧，遇空时观察栈顶 candidate：右孩子存在且不等于 lastVisited，就转入右子树；否则左右都完成，可以弹出并输出 candidate，同时让 lastVisited 指向它。

| 阶段 | 栈（顶→底） | 行为 | lastVisited | 输出 |
| --- | --- | --- | --- | --- |
| 左降至 2 | `[2,1]` | 2 的右子树 4 未完成，进入 4 | null | `[]` |
| 处理 4 | `[4,2,1]` | 4 无右孩子，输出并弹出 | 4 | `[4]` |
| 返回 2 | `[2,1]` | 右孩子就是 lastVisited，输出 2 | 2 | `[4,2]` |
| 返回 1 | `[1]` | 右子树 3 未完成，进入 3，再左降到 5 | 2 | `[4,2]` |
| 处理 5 | `[5,3,1]` | 输出 5 | 5 | `[4,2,5]` |
| 返回 3 | `[3,1]` | 无右孩子，输出 3 | 3 | `[4,2,5,3]` |
| 返回 1 | `[1]` | 右子树根 3 已完成，输出 1 | 1 | `[4,2,5,3,1]` |

lastVisited 比较节点身份而非 value。两个值相同的节点不能被误判为同一棵已完成子树。

正确性：栈保存尚未输出的祖先路径；向左下降先处理左子树，candidate 只有在右子树为空或刚完成时才输出。后序中一个子树的根最后输出，所以“最近完成的是右子树根”能识别该右子树已经全部完成。每个节点只入栈、出栈一次，且右子树不会重复进入。

## 7. 层序：队列如何保证层次

根先入队，弹出后记录值，左右孩子依次加到队尾。

| 出队值 | 加入孩子 | 队列（首→尾） |
| --- | --- | --- |
| 初始 | 1 | `[1]` |
| 1 | 2、3 | `[2,3]` |
| 2 | 4 | `[3,4]` |
| 3 | 5 | `[4,5]` |
| 4 | 无 | `[5]` |
| 5 | 无 | `[]` |

已发现但未访问的同层节点始终排在新发现孩子之前，左右入队顺序保持同层从左到右。每个节点有唯一父节点，故恰好入队一次。若要按层返回二维结果，可在每层开始时记录当前 queue.size()，只处理该批节点；本次 API 返回扁平层序数组。

## 8. 时间与空间：输出成本也要算

n 为实际节点数，h 为树的层数，w 为最大层宽，m 为输入数组长度。

| 方法 | 时间 | 控制辅助空间，不计结果 |
| --- | --- | --- |
| 层序工厂 | O(m) | O(w) 队列，另需 O(n) 节点存储 |
| 三种递归遍历 | O(n) | O(h) 调用栈 |
| 三种迭代 DFS | O(n) | O(h) 显式栈上界 |
| 层序遍历 | O(n) | O(w) 队列 |

队列可能同时包含相邻两层的一部分，但总量仍为 O(w)，不是要求它任何时刻都恰好等于某层宽。DFS 栈在退化树某些遍历中可以更小，但统一最坏上界为 O(h)。

当前各遍历先用 ArrayList<Integer> 累积，再转 int[]，两份结果存储同时存在时仍为 O(n) 总阶数，含装箱对象开销。返回数组 O(n)，输出本身就不可能降到常数空间。空树控制成本 O(1)。

递归与迭代都是合理 O(n) 时间，没有凭空的渐进加速。迭代消除深层方法调用风险，但状态更显式，后序更容易写错。递归对很深的树可能抛 StackOverflowError；测试深链只调用迭代版本，不能宣传递归已支持任意深度。
