# 二叉搜索树（Binary Search Tree）：利用顺序排除子树

[树专题总览](Tree.md) · [普通二叉树](BinaryTree.md) · [Java 实现](../../src/learning/datastructures/tree/BinarySearchTree.java)

学习日期：2026-11-11（北京时间）。本节实现不自动平衡的整数二叉搜索树，重点是搜索规则、重复值策略和删除。它不是 AVL、红黑树，也不承诺所有操作都为 O(log n)。

## 1. 从普通二叉树到搜索树

普通二叉树没有值的大小规则，查找某个值可能需要遍历整棵树 O(n)。二叉搜索树（BST）增加严格约束：每个节点的**整棵左子树**都小于该节点，**整棵右子树**都大于该节点，两个子树自身也满足相同约束。

依次插入 `8,3,10,1,6,14,4,7,13`：

```text
           8
         /   \
        3     10
       / \      \
      1   6      14
         / \     /
        4   7   13
```

中序得到 `[1,3,4,6,7,8,10,13,14]`。排序性来自搜索树约束，不是“只要中序遍历就自然有序”。仅验证直接孩子大小也不够：根 8 的左子树中出现 9，即使它大于自己的父节点，仍违反祖先 8 的上界。

## 2. 接口与重复值策略

本实现是整数集合，一个值最多一个节点。原来的 BinaryTree 允许重复值并按指定形状构造，本类通过 add 的比较路径建立结构，二者接口目标不同。

| 方法 | 约定 |
| --- | --- |
| add(value) | 新值加入返回 true；已有值返回 false，结构和 size 不变 |
| contains(value) | 存在为 true，空树也可调用 |
| remove(value) | 删除成功返回 true；缺失返回 false，不改结构 |
| min()/max() | 返回最值；空树抛 NoSuchElementException |
| size()/isEmpty() | 不同值的数量、判空 |
| inorder() | 返回独立且严格递增的 int 数组，空树返回空数组 |

所有 int 值均合法，包括 0、负数和两端边界。比较直接使用 `<`、`>`、`==`，不能通过 `a-b` 判断大小，否则可能溢出。计数达到 Integer.MAX_VALUE 后拒绝新增并抛 IllegalStateException，重复插入仍返回 false，实际规模还受内存限制。节点私有，不提供并发安全保证。

其他合理重复策略包括节点内记录频次、保存键值映射并覆盖值；也可约定重复键固定放一侧，但要相应修改删除和有序性证明。本次不混用这些策略。

## 3. 查找：为什么可以只走一边

查找 7 的完整路径：

| 当前节点 | 比较 | 下一步及排除理由 |
| --- | --- | --- |
| 8 | 7 < 8 | 进入左子树，右侧所有值 > 8，不可能为 7 |
| 3 | 7 > 3 | 进入右子树，左侧所有值 < 3，不可能为 7 |
| 6 | 7 > 6 | 进入右子树 |
| 7 | 相等 | 返回 true |

查找 5 会走 `8→3→6→4→null`，返回 false。每轮不变量是：如果目标存在，它就在 current 指向的子树里；大小约束使排除另一侧安全。有限树每轮下降一层，因此必然结束。

优化来自减少访问节点，不是计算哈希，也不是在数组上二分。高度若很大，排除的一侧可能很小，实际访问仍可达到 n。

## 4. 插入：找到本该出现的位置

用相同查找规则下降，并保存 parent。遇到相等直接返回 false；走到 null 后，把新节点接到 parent 对应的空孩子位置。空树没有 parent，直接设 root。

例如在上图插入 5：

```text
比较路径：8 → 3 → 6 → 4 → 右侧 null
局部变化：   4              4
                            \
                             5
```

沿路径的每一次比较都给新值施加一个祖先上界或下界。走到空位时它满足这些约束，插入叶节点不会改变原有节点的大小关系。这比“随便挂在某个小节点右边”更严格。

本例仅用于解释插入，后续删除图示各自说明起始状态，避免把额外插入的 5 混入 main 的初始树。

## 5. 删除：先找到节点，再分类处理

朴素替代方案是收集全部值、去掉目标再重建树，至少访问全部节点，还可能重建出退化树。局部删除沿查找路径定位，只调整必要连接，时间 O(h)。

### 5.1 叶节点：把父连接设为 null

删除初始树中的 1：

```text
删除前：    3              删除后：    3
          / \                        \
         1   6                        6
```

删除唯一的根节点时没有父节点，必须令 root=null。只给局部变量赋 null 不会修改树入口。

### 5.2 只有一个孩子：孩子接替原位置

删除初始树中的 14，它只有左孩子 13：

```text
原来： 10 →右 14          修改：10.right = 13
             /
            13
```

13 及其子树已受祖先 10 的下界约束，所以接替不会违反顺序。只有右孩子时同理。若被删的是根，root 直接指向唯一孩子。源码统一用 `replacement = left != null ? left : right`，叶节点时 replacement 就是 null。

### 5.3 有两个孩子：使用中序后继

选择右子树的最小节点 successor（一路向左走），它是大于当前值的最小值，且一定没有左孩子。因此先用 successor.value 替换目标值，再把真正摘除的目标转为 successor，就退化为“至多一个孩子”的情况。

为什么替换正确？旧左子树所有值都小于旧根，而后继大于旧根，所以它们也小于新根；右子树其他值都大于后继（不允许重复），因此仍大于新根。最后摘除旧后继位置，恢复值的唯一性。

**后继恰好是直接右孩子：**删除初始树的根 8，后继为 10，10 没有左孩子，但带有右子树 14。

```text
原来：       8                    结果：       10
           / \                              /  \
          3  10                            3    14
               \                                /
                14                             13
               /
              13
```

将根值改为 10 后，必须把原 10 的右孩子 14 接回根的右侧，不能直接设为空。

**后继位于右子树深处，且有右孩子：**下面是独立例子，由 `20,10,40,30,50,25,35,27` 构成。

```text
删除前：         20                 删除后：         25
               /  \                              /  \
              10   40                           10   40
                  /  \                              /  \
                 30   50                           30   50
                /  \                              /  \
               25   35                           27   35
                 \
                  27
```

后继为 25，父节点为 30。替换根值后执行 `30.left = 25.right`，保留 27。丢掉这条右子树是双孩子删除的常见错误。

## 6. 代码如何统一删除分支

remove 先沿比较路径找到 current 和 parent。若 current 有两个孩子，寻找 successor 和 successorParent，替换值后把 current/parent 改为后继及其父节点。

此时 current 最多一个孩子，统一处理：

```text
replacement = current.left 非空 ? current.left : current.right
parent 为空：root = replacement
parent.left 与 current 是同一对象：parent.left = replacement
否则：parent.right = replacement
```

比较的是节点身份，不是值。因为复制后继值后，摘除前内部可能暂时有两个值相同的节点，不能仅凭值决定连接方向。操作完成后清除摘除节点的左右引用，size 只减少一次；找不到目标直接返回 false。

正确性由上节三个局部替换证明及查找路径保证。对于双孩子节点，从 root 到目标再到右子树最小值，总步数仍 O(h)，没有再次遍历整棵树。整个实现迭代，不使用深度相关的方法调用栈。

## 7. 最值与有序遍历

最小值在最左端：只要有左子树，其中的值就更小；沿 left 到尽头即可。最大值对称地沿 right 查找，时间 O(h)。空树没有合法整数哨兵值，所以 min/max 抛异常。

中序遍历用显式栈保存左侧路径。递归定义为“左子树值、根值、右子树值”；根据严格搜索树规则，三部分都严格递增且边界有序，所以整体严格递增。inorder 直接创建长度 size 的 int 数组，不会修改内部节点；快照被调用方修改不影响树。

## 8. 高度决定性能：不能保证 O(log n)

```text
依次插入 1、2、3、4：
1
 \
  2
   \
    3
     \
      4
```

此时 h=n，contains(4) 访问所有节点。连续按升序加入 n 个不同值，需要约 `0+1+...+(n-1)` 次比较，总时间 O(n²)。降序同样会退化。

| 操作 | 时间 | 辅助空间，不计新增节点/返回值 |
| --- | --- | --- |
| contains/add/remove/min/max | O(h)，最坏 O(n) | O(1)，迭代 |
| size/isEmpty | O(1) | O(1) |
| inorder | O(n) | O(h) 显式栈，另有 O(n) 返回数组 |

节点总存储 O(n)。h 按层数，空树操作为 O(1)。树较平衡时 h=O(log n)，但本实现没有维持该条件；不能把随机插入的经验当作任意操作序列的保证。接下来 AVL/红黑树通过额外平衡规则限制高度，代价是更新更复杂。

## 9. 与数组、哈希表的取舍

| 结构 | 成员查找 | 动态更新 | 有序输出 |
| --- | --- | --- | --- |
| 无序数组 | O(n) | 插入末端方便，删除需明确保序要求 | 需要排序 |
| 有序数组 | 二分 O(log n) | 中间插删通常 O(n) 搬移 | 天然有序 |
| 哈希表 | 良好分布下期望 O(1) | 分布、负载及扩容影响成本 | 不保证顺序 |
| 本节普通 BST | O(h) | O(h)，无需整体搬移 | 中序 O(n) |

BST 适合学习有序查找、范围操作的基础，但本次只提供集合增删查与最值，不声称已实现范围查询、排名或第 k 小。Java TreeSet/TreeMap 使用平衡搜索树机制，与本节未平衡实现的性能保证不同。

## 11. 边界、练习与面试表达

需要检查空树最值异常、重复插入、缺失删除、唯一根删除、根只有左/右孩子、叶子与内部单孩子、后继直接是右孩子、后继位于深处且有右孩子、极值整数、升降序退化、快照独立性。

> BST 的大小规则约束整棵子树，所以查找每次能排除一侧。插入接到搜索路径末端。删除叶子直接断开，单孩子节点用孩子接替，双孩子节点用右子树最小值替换，再删除那个至多一个孩子的后继。复杂度是 O(h)，普通 BST 可能退化，不能直接承诺 O(log n)。

练习：手画删除第 5 节的 20 并保留 27；解释为何不能只比较直接孩子判断 BST；推导升序构建 O(n²)。相关题为 700「二叉搜索树中的搜索」、701「二叉搜索树中的插入操作」、450「删除二叉搜索树中的节点」、98「验证二叉搜索树」。本次不是这些题的独立解答，题目接口及重复键规则需要单独核实。
