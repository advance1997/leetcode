## 2. 为什么队首和队尾要分开

```text
出队方向 ← 队首 [10] [20] [30] 队尾 ← 新元素从这里入队
```

先加入 10、20、30，按队列删除应依次得到 10、20、30。数值大小不决定顺序，重复值仍代表不同入队事件。

| 操作 | 普通队列 | 双端队列 |
| --- | --- | --- |
| addLast(value) | 尾部入队 | 尾部加入 |
| removeFirst() | 首部出队 | 首部删除 |
| peekFirst() | 查看下一个待出队元素 | 查看首元素 |
| addFirst(value) | 不提供 | 首部加入 |
| removeLast()/peekLast() | 不提供 | 尾部删除/查看 |
| size()/isEmpty()/toArray() | 数量、判空、首到尾快照 | 同左 |

四个教学类允许任意 int 和重复值。空时查看或删除统一抛 NoSuchElementException，且不修改状态；快照独立。没有以 -1、0 表示空，也没有覆盖最旧元素的丢弃策略。

## 3. 从直觉实现到高效实现

朴素数组队列把队首固定在下标 0，每次出队后整体左移 n-1 个元素，因此出队 O(n)。若只递增首尾下标而不复用前部空间，物理尾部到末端后会产生“前面有空位却不能入队”的假满。

环形数组用逻辑下标映射物理槽位，出队只移动 head，尾部到末端后回到 0，复用前面空位。它是数组索引回绕，不是节点相互引用的循环链表。

链表队列若只有 head，尾插需要遍历 O(n)。同时维护 tail 就能直接接新节点，头删也无需遍历，二者均 O(1)。双端队列还要尾删，单链表即使有 tail 也不能直接找到前驱，因此链式双端实现采用双向链表。

## 4. 完整操作对照

| 操作 | 普通队列序列（首→尾） | 输出 |
| --- | --- | --- |
| addLast(10)、addLast(20)、addLast(30) | `[10,20,30]` | — |
| removeFirst() | `[20,30]` | 10 |
| addLast(40) | `[20,30,40]` | — |
| peekFirst() | `[20,30,40]` | 20，不移除 |
| 连续 removeFirst() | 最终 `[]` | 20、30、40 |

双端队列在 `[20,30,40]` 上 addFirst(5) 得 `[5,20,30,40]`，removeLast() 返回 40，剩余 `[5,20,30]`。这种混合操作不再遵循纯 FIFO；数据结构允许什么，与业务选择什么顺序，要分开理解。

## 5. 成本与选择

n 为有效元素数量，C 为数组保留容量。

| 实现 | 加入 | 删除/查看 | 存储与代价 |
| --- | --- | --- | --- |
| 数组队列/双端队列 | 均摊 O(1)，扩容单次 O(n) | O(1) | O(C)，不缩容，偶发复制 |
| 链式队列/双端队列 | O(1)，每次分配节点 | O(1) | O(n) 可达节点，有对象及引用开销 |

所有快照均为 O(n) 时间及返回空间。链式 O(1) 基于通常节点分配成本模型，不是 JVM 实时响应承诺。数组删除不缩容，因此峰值后内存可能明显大于当前 n。泛型数组应清理废弃引用；本实现 int 清零仅便于观察，有效性仍由 size 确定。

## 6. Java 标准库与应用

常见普通队列用法为 `Queue<Integer> queue = new ArrayDeque<>();`，双端用 `Deque<Integer> deque = new ArrayDeque<>();`。LinkedList 也实现 Queue 和 Deque，但不是所有场景都更快。ArrayDeque 禁止 null，且不支持并发修改。

| Java 标准接口 | 成功行为 | 空/满等失败情形 |
| --- | --- | --- |
| add / offer | 加入 | 有容量限制时 add 通常抛异常，offer 通常返回 false |
| remove / poll | 删除队首 | 空时前者抛异常，后者返回 null |
| element / peek | 查看队首 | 空时前者抛异常，后者返回 null |

本仓库命名 peekFirst/peekLast 的 int 教学接口在空时抛异常，**不同于**标准 Deque.peekFirst/peekLast 的 null 约定，调用时不能混用。int 不可表达 null，需要按明确契约处理空值。

普通队列用于任务先来先处理、BFS 待访问节点；双端队列可用于两端调度、单调队列、0-1 BFS 等，后两者还需要专门算法不变量，不能只会容器就宣称掌握算法。

## 7. 常见错误与复述

错误集中在：仅用首尾重合区分空满；回绕后直接复制物理数组；Java 负数取余产生负下标；删空后链表 tail 残留；双端尾删只修改一侧引用；把所有 Queue 实现都视为 FIFO（例如优先队列不满足）；用快照后的总耗时冒充 O(1) 操作。

> 队列从尾进、从首出。数组实现用环形下标复用空间，维护 size 区分空满，扩容时从逻辑头开始依次复制。链式队列保存 head 和 tail，尾插头删无需遍历，删除最后一个节点时同时归空。双端队列还支持反向操作，数组需要前后回绕，链式实现需要前驱引用。

建议先手画数组回绕再扩容，之后画链表唯一节点删除与重入队。最后用同一组双端操作对照两种实现。文档完成不代表学习者完成这些练习。
